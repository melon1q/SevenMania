# BMS Player 7+1 Key (C++ / Windows)

Windows 네이티브 C++로 만든 BMS 재생 프로토타입입니다. 7+1키를 중심으로 5키, 10키, 14키, PMS 9키도 재생합니다(모드별 현황은 [키 모드 지원 문서](docs/KeyModeSupport-2026-11-09.md)). 곡 폴더를 고르면 하위 폴더까지 `.bms`, `.bme`, `.bml`, `.pms` 파일을 검색합니다. 파일명과 제목, 아티스트, 난이도, BPM, 키 모드 및 실행 차단 사유를 목록에 보여줍니다.

## 빌드

Visual Studio 2026의 **Desktop development with C++** 구성 요소와 Windows 10/11 SDK가 필요합니다. 프로젝트 폴더에서 다음을 실행합니다.

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

실행 파일은 `build/Release/BmsPlayer.exe`에 생성되며 `Assets/app-icon.ico`를 프로그램 아이콘으로 포함합니다.

## 사용

최신 렌더링 최적화와 실제 FREEDOM DiVE 측정 결과는 [렌더링 성능 문서](docs/RenderingPerformance.md)에 정리했습니다. 미스 레이어·BGA·텍스트 애니메이션을 유지하면서 텍스트 캐시, 미스 이미지 뒤의 불필요한 합성 제거, 음영·건반 계산을 개선했습니다.

곡 목록은 화면 오른쪽에서 창 너비의 1/3을 차지하며 `레벨 → 곡명/채보`만 표시합니다. 선택 항목은 파란색으로 강조하고 아티스트·BPM 등 상세 정보는 왼쪽에 표시합니다. 실행 불가 채보는 기본 목록과 난이도 전환에서 제외하며, 하단 **숨겨진 파일 보기** 버튼으로 별도 목록을 엽니다. 숨겨진 채보를 선택하면 왼쪽에서 차단 이유를 볼 수 있으며 플레이는 차단됩니다. **곡 목록으로 돌아가기**를 누르면 이전 곡·난이도 선택으로 돌아갑니다.

콤보 증가와 판정 표시 시 공통 easeOutBack 크기 애니메이션을 적용합니다. 글자 중심에서 85% 크기로 시작해 0.2초 동안 살짝 확대된 뒤 원래 크기로 돌아옵니다. 콤보가 증가하면 애니메이션을 다시 시작하며, 0콤보는 표시하지 않습니다. 판정이 이미 표시 중이면 문구·색·표시 시간만 갱신하고 애니메이션은 끕니다. 판정이 사라진 뒤 다시 나타날 때 애니메이션을 재생합니다.

점수는 0점에서 시작하며 모든 노트가 GREAT!!(PGREAT)인 풀퍼펙트는 정확히 1,000,000점입니다. 판정별 획득 비율은 GREAT!! 100%, GREAT 80%, GOOD 50%, BAD·POOR 0%입니다. 모든 노트의 총 배점은 같고 롱노트는 시작·끝에 50%씩 배분합니다. 소수점 배점을 누적한 뒤 표시할 때만 정수로 계산하여 채보 길이에 따른 만점 오차가 없습니다. BAD·POOR는 기존 점수를 깎지 않습니다. 게임오버 시에는 그때까지 획득한 점수를 리절트에 표시합니다. 랭크 기준은 S 95만점, AAA 90만점, AA 80만점, A 70만점, B 60만점, C 50만점 이상이며 나머지는 F입니다.

리절트에는 곡 선택 화면을 흐리게 처리한 배경 위에 곡 제목, 레벨, BPM·아티스트, 랭크와 점수를 표시합니다. 오른쪽 아래 `NEXT` 버튼이나 `Enter` 키를 누르면 곡 목록으로 돌아갑니다.

곡 폴더 검색과 재생 전 음원 디코딩은 백그라운드에서 실행합니다. 준비 중에도 창이 입력에 응답하며 `Esc`로 불러오기를 취소할 수 있습니다. 준비가 완료되면 재생을 시작합니다.

앱을 시작하거나 곡 폴더를 불러오면 실행 파일 옆 `Songs` 폴더 전체를 곡 경로로 사용하고 그 아래 모든 곡을 재귀 검색합니다. 폴더 선택창도 항상 `Songs`에서 열립니다. 외부 곡 폴더를 선택하면 음원·BGA를 포함한 전체 복사본을 `Songs` 아래에 저장한 뒤 라이브러리 전체를 다시 읽으므로 기존 곡들도 목록에 계속 표시됩니다. 같은 원본 폴더를 다시 선택하면 크기·수정 시간이 바뀐 파일만 갱신하며, 이미 저장된 복사본을 다시 복사하지 않습니다. 복사·채보 분석 진행률을 상태줄에 표시합니다. 처음 가져올 때는 전체 곡 파일을 복사하는 시간이 필요합니다.

채보 검색은 곡 폴더별 음원 목록·공유 정의를 재사용하고 최대 4개 폴더를 병렬 분석합니다. 실제 Cat's_rule 폴더의 분석 시간이 2.76초에서 0.42초, slic_hertz는 0.55초에서 0.047초로 줄었습니다. 복사 시간과 음원 디코딩은 이 측정에 포함하지 않습니다. 자세한 저장 방식과 검증은 [곡 라이브러리 문서](docs/SongLibrary.md)를 참고하세요.

설정 아래쪽의 **기어 위치**에서 왼쪽 / 가운데 / 오른쪽을 선택합니다. 기본값은 가운데이며, 레인 전체 폭의 중심을 게임 화면 중심에 맞춥니다. 판정선 아래 건반은 누르는 동안 어두워지고, 놓으면 원래 색으로 돌아옵니다.

**GPU 노트 렌더링 (DirectComposition)**은 기본으로 켜져 있습니다. 하드웨어 Direct3D 11 / Direct2D로 노트·롱노트와 레인 커버를 그리고, 투명한 판정 텍스트·스플래시를 그 위에 합성합니다. BGA 준비와 일부 HUD는 CPU에서 처리합니다. GPU 초기화나 출력이 실패하면 해당 플레이는 CPU 렌더링으로 돌아갑니다. 렌더 FPS와 모니터의 실제 표시 주사율은 다릅니다.

GPU 렌더링은 별도 텍스처에 완성하고, Windows 표시 큐에 자리가 있을 때만 화면으로 전달합니다. 표시 대기는 0ms로 조회하며 `DXGI_PRESENT_DO_NOT_WAIT`의 일시적인 큐 포화는 GPU 오류로 취급하지 않습니다([Microsoft DXGI 문서](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-present)). 무제한 FPS는 Windows 합성 주사율 대기로 제한하지 않으며 실제 표시 빈도는 모니터에 따릅니다. 판정·콤보·키 가이드와 스플래시 원본은 최대 32개 GPU 비트맵 캐시에서 재사용하고, 매 프레임 큰 투명 HUD 버퍼를 만들거나 전송하지 않습니다. 노트 클립 범위는 CPU와 동일하게 판정선 아래 38px까지 유지하고 건반을 그 위에 합성합니다.

플레이 진입 시 곡 선택 화면의 미리보기 음원 캐시·대기 작업과 배경 캐시를 해제합니다. 곡 목록과 계산된 공통 하이라이트 위치는 유지하며, 목록 복귀 후 선택한 곡의 미리보기는 다시 준비합니다. 플레이 종료·중단 시 해당 곡의 디코딩된 PCM, 음원 이벤트, 믹싱 버퍼와 GPU 자원도 해제합니다. 효과음과 결과 배경에 필요한 정보는 유지합니다.

앱에서 **곡 폴더 열기**를 눌러 곡 폴더를 불러옵니다. 플레이 가능한 7+1키 채보를 선택해 `Enter`로 실행합니다. 곡 목록에서 **Space** 또는 **설정 (Space)** 버튼으로 설정창을 엽니다. 목록·버튼에 포커스가 있어도 Space로 열립니다. 설정창은 `Esc` 또는 **닫기**로 닫습니다.

곡 선택은 **곡 폴더 → 곡 선택 → 플레이** 순서입니다. 같은 폴더에서 곡 기본 제목·키 모드가 같은 채보는 한 행으로 묶이며, 난이도는 실제 `#PLAYLEVEL` 오름차순으로 정렬됩니다. 제목 끝의 `[LIGHT 7]` 같은 대괄호 채보 표기를 분리하며, 같은 폴더에 기본 제목 채보가 있으면 `(carnival)`·`- SINGULARITY` 같은 뒤쪽 표기도 묶습니다. 아티스트에 채보 제작자가 추가되어 달라도 같은 곡으로 선택합니다. 원본 제목·부제·아티스트·레벨은 수정하지 않으며, 선택한 채보의 실제 정보를 화면에 표시합니다. 각 곡의 가장 낮은 레벨이 기본 선택이고, 목록에서 `←` / `→`로 같은 곡의 채보를 바꾼 뒤 `Enter`로 시작합니다. 선택한 난이도와 실행 가능 여부는 목록에 반영됩니다.

설정창은 [게임플레이] [그래픽] [사운드] [기타] 탭으로 나뉩니다. 게임플레이 탭에는 DirectComposition, 노트 색, 노트 세로 크기, 밝기와 배속, 레인 투명도와 커버, 키 배치, 기어 위치가 있습니다. 그래픽 탭에는 프레임 목표와 화면 모드가 있습니다. 사운드 탭에서 마스터·노래·키음·효과음 볼륨을 각각 0~100%로 조절하며, 효과음은 추가 예정입니다. 기타 탭은 현재 비어 있습니다. 설정창은 스크롤할 수 있으며, 스크롤 중 마우스 휠이 드롭다운 설정값을 바꾸지 않습니다. 화면 모드를 전체화면, 보더리스 창화면, 창화면 중에서 고를 수 있습니다. 설정창에는 **키 배치 변경**, **기본 키로 복원**, **사용법**, **판정선 위치**, **레인 투명도**, **레인 커버**, **레인 구분선**, **노트 밝기**, **노트 배속**, **프레임 목표**와 **레인별 노트 색상**이 있습니다. 기본 판정선은 게임 화면 높이의 위에서 2/3(아래에서 1/3) 지점입니다. 판정선 위치 슬라이더를 움직이면 미리보기가 즉시 갱신되고, 값은 실제 플레이 화면의 판정선에도 적용됩니다. 위치는 화면 안에서 위아래로 넓게 조절할 수 있습니다. 레인 배경은 검은색이며 틈 없이 화면 위부터 아래 끝까지 이어집니다. 구분선은 1픽셀 두께이며 기본값은 스크래치–1번 사이만 켜져 있습니다. 설정창의 SCR|1, 1|2~6|7 버튼으로 각 경계를 개별적으로 켜고 끕니다. 레인 투명도는 0%(불투명)~100%(배경 숨김)로 조절하며, 기본값은 34%입니다. 노트 밝기는 0%(BGA 끔)~100%를 10단위로 설정합니다. 노트·판정선·키 표시는 선명하게 유지합니다. 노트 세로 크기는 4~32px를 2px 단위로 조절하며 기본값은 12px입니다. 일반 노트와 롱노트 머리·몸통에 적용됩니다. 기본 키는 스크래치 `Left Shift`, 건반 `S D F Space J K L`입니다. 키 배치 변경 후 스크래치와 1~7번 건반 순서로 서로 다른 키를 입력하세요. 변경 중 `Esc`를 누르거나 창을 떠나면 기존 배치를 유지합니다. 색상은 각 레인마다 색상 견본이 있는 10색 기본 팔레트에서 선택합니다. 일반 노트·롱노트의 머리·롱노트 몸체와 레인 입력 표시가 선택 색상을 사용합니다. 설정과 마지막으로 불러온 곡 폴더는 `%APPDATA%\BmsPlayer\keybindings.ini`에 저장되며, 앱을 다시 실행하면 해당 폴더의 채보 목록을 자동으로 다시 검색합니다.

레인 커버가 없으면 노트는 화면 최상단부터 표시됩니다. 커버는 설정에서 위쪽~판정선 거리의 0~100%를 가릴 수 있으며 기본값 0%(없음)입니다. 미리보기와 함께 조절하고 재실행 후에도 유지됩니다. 커버는 노트와 키 빔 표시만 가리며 오디오와 판정 시각은 유지합니다. 키 빔의 높이는 화면 최상단~판정선 거리의 1/2입니다. 판정선 바로 아래에는 스크래치 원판과 밝고 어두운 건반이 번갈아 있는 컨트롤러 패널을 표시하며, 입력 시 건반의 눌림 깊이가 변합니다. 건반 표시줄은 제거했습니다. 키 이름 아래부터 화면 끝까지는 패널 배경색으로 채워 레인·구분선이 비치지 않습니다. 건반 레인 폭은 68px, 스크래치는 104px이며 노트·빔·구분선도 같은 배치에 맞춥니다. 스크래치 원판은 입력이 없으면 회전하고 스크래치 키를 누르면 현재 각도에서 정지하며, 놓으면 다시 회전합니다. 키를 누르면 모든 레인에서 중앙의 가는 폭이 레인 전체 폭으로 0.1초 동안 넓어지는 파란 키 빔이 나타납니다. 판정선에 가까울수록 불투명하며 위로 갈수록 투명합니다. 키를 놓으면 같은 속도로 폭이 줄어 사라지고, 애니메이션 도중 재입력하거나 놓아도 현재 폭에서 자연스럽게 반전됩니다. 롱노트의 파란 테두리 강조는 제거했습니다. 노트가 없는 시점에도 레인 키를 누르면 최근에 지나간 해당 레인의 노트 키음이 재생됩니다. 첫 노트 전에는 첫 노트의 키음을 사용하고, 해당 레인에 노트가 없거나 무음 샘플이면 소리가 나지 않습니다. 이 입력은 노트 판정을 변경하지 않습니다. 노트의 시작 판정에 성공하면 콤보가 1씩 증가하고, 미스·롱노트 유지 실패 시 0으로 초기화합니다. 롱노트 꼬리는 콤보를 중복 계산하지 않습니다. 성공한 레인의 판정선에 파랑~하늘색 원이 생성되며, 0.18초 동안 easeOutBack으로 확대된 뒤 크기를 유지하면서 0.10초 동안 빠르게 투명해져 사라집니다. 빈 키 입력은 콤보나 히트 이펙트를 만들지 않습니다. 노트 시작 판정은 `PGREAT`(±16.67ms), `GREAT`(16.67~33.33ms), `GOOD`(33.33~116.67ms), `BAD`(116.67~250ms), 이후 놓친 노트는 `POOR`로 표시합니다. 롱노트는 꼬리 시각 ±116.67ms 안에서 키를 놓으면 `PGREAT`, 너무 일찍 놓으면 `POOR`, 너무 늦게 놓거나 늦게까지 누르고 있으면 `BAD`입니다. 노트가 없는 키 입력에는 판정 텍스트를 표시하지 않으며, 해당 키의 키음 입력은 유지합니다. 판정 문구는 기존의 2배 크기로 표시됩니다. BAD·POOR 판정은 콤보를 초기화합니다.

판정선 아래 키 패널 다음에는 흰색 게이지를 표시합니다. 게임 시작 시 100%로 가득 차 있으며 GREAT!!·GREAT는 유지, GOOD는 1%p, BAD는 3%p, POOR는 5%p 감소합니다. 게이지는 회복되지 않으며 0%에 도달하면 오디오·BGA를 중단하고 현재 랭크와 점수로 리절트 화면을 표시합니다. 배속 아이콘 칸에는 현재 배속을 표시하고, 옆의 3칸은 후속 HUD 아이콘을 위한 빈 슬롯입니다. `F1`은 노트 배속을 0.25x 낮추고 `F2`는 0.25x 올립니다 (0.50x~10.00x). `PageDown`은 BGA 밝기를 낮추고(어둡기 +10), `PageUp`은 밝기를 높입니다(어둡기 −10). 설정값은 재실행 후에도 유지됩니다. 배속은 노트가 내려오는 화면 속도만 바꾸며 오디오와 입력 기준 시각은 유지됩니다. `Esc`로 목록으로 돌아갑니다. 창이 포커스를 잃으면 재생을 멈춥니다.

프레임 목표는 **60 / 144 / 240 / 400 FPS 또는 무제한**이며 기본값은 **240 FPS**입니다. `WM_TIMER` 대신 고해상도 waitable timer와 일정한 프레임 마감 시각으로 화면을 갱신합니다. 144 FPS의 6.944ms, 240 FPS의 4.167ms, 400 FPS의 2.5ms 간격을 유지하고, 늦어진 프레임은 몰아서 그리지 않습니다. 무제한은 프레임 간 대기 없이 가능한 속도로 렌더링합니다. BGA와 레인 배경은 별도 메모리 표면에 합성해 이미지·미스 레이어·창 크기가 바뀔 때만 다시 그리므로, 매 프레임의 전체 화면 이미지 확대·합성 비용을 줄입니다. 노트는 32비트 화면 버퍼에 직접 래스터화해 노트마다 발생하던 GDI 채우기 호출을 없앴고, 판정 상태는 바이트 배열로 저장합니다. 재생 화면은 측정된 렌더 FPS와 목표 FPS를 함께 표시합니다. 오디오 재생 시작에 맞춘 연속 시간 기준으로 노트와 입력 시각을 계산합니다. 오디오 버퍼가 부족해 출력이 일시적으로 멈춰도 곡 진행 속도는 유지하고, 회복 시 지난 오디오 구간을 건너뛰어 현재 시각에 맞춥니다. 노트 머리와 롱노트 끝에는 소수점 픽셀 경계 보간을 적용합니다. 모니터에서 144·240Hz로 보려면 **Windows 디스플레이 설정의 주사율도 해당 값**으로 설정되어 있어야 합니다. 렌더 FPS는 실제 모니터 표시 빈도의 측정값이 아닙니다.

BGA 애니메이션은 원본 픽셀과 부드럽게 확대된 이미지별 결과를 캐시하고, 레이어·미스 레이어·음영을 픽셀 버퍼에서 합성합니다. 원본 캐시는 64MiB, 확대 캐시는 256MiB를 상한으로 오래된 항목부터 제거합니다. 실제 FREEDOM DiVE 플레이 장면을 사용한 렌더링 부하 측정 방법과 결과는 [렌더링 성능 문서](docs/RenderingPerformance.md)에 있습니다.

이전 버전의 `SetTimer(4ms)` 방식은 Windows의 최소 10ms 간격에 제한되었습니다. 현재 버전은 그 방식을 제거했습니다. [SetTimer 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-settimer), [고해상도 waitable timer 문서](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw)

샘플 정의(`#WAVxx`)가 현재 채보에 없으면 같은 폴더의 다른 BMS 채보에서 빠진 정의를 보완하며, 채보에 이미 정의된 샘플을 우선합니다. 다른 채보에도 정의가 없는 ID는 BMS의 무음 오브젝트로 처리하며 노트·롱노트와 BGM 시각을 유지합니다. 정의된 파일이 없으면 같은 폴더에서 같은 기본 이름의 WAV·OGG·MP3를 찾아 연결합니다. WAV와 MP3는 Windows Media Foundation으로, OGG Vorbis는 포함된 공개 도메인 `stb_vorbis` 디코더로 재생 전에 PCM으로 변환합니다. OGG 재생에 별도 Windows 코덱을 요구하지 않습니다. 사전 디코딩 메모리는 채보당 512MB로 제한합니다. 디코더 원본과 라이선스 표기는 `third_party/stb_vorbis.c`에 포함되어 있습니다.

## 채보 해석 범위

- `.bme` 확장자, 7키 확장 채널, `#PLAYER` 및 실제 채널을 함께 분석합니다. 모드를 판별할 수 없는 채보는 실행을 막습니다. `.bms`에서 7키 확장 채널(18/19)이 없으면 5키로 분류하며 7키로 바꾸지 않습니다.
- 5키, 7키, 10키, 14키, PMS 9키는 실행할 수 있습니다. `Tab`으로 키 모드별 목록을 거를 수 있습니다. 그 외 플레이 방식은 곡 목록에 표시하지만 실행할 수 없습니다. 모드별 키 배치, 컨트롤러, 알려진 한계는 [키 모드 지원 문서](docs/KeyModeSupport-2026-11-09.md)에 있습니다.
- UTF-8과 Shift-JIS 헤더를 읽고, 일반 노트와 스크래치, BGM, 마디 길이, 기본·직접·확장 BPM, STOP, 고정 선택값 `#RANDOM`/`#IF`, `#LNOBJ`, `#LNTYPE 1` 롱노트를 처리합니다.
- BGA는 게임 화면 전체를 채우며, `#BMPxx` 이미지와 채널 `04`(기본), `07`(레이어), `0A`(두 번째 레이어)를 재생 위치에 맞춰 겹쳐 표시합니다. `#BGAxx`의 단순 사각형 자르기도 적용합니다. 놓친 노트나 롱노트 홀드 실패가 나면 채널 `06` 미스 레이어를 2.5초 동안 화면 위에 표시합니다. 채보와 같은 이름의 BGA 이미지·영상 파일을 우선 읽고, 없으면 같은 폴더에서 이름에 `bga`가 포함된 파일을 우선합니다. 그 후보 중 MP4·MPEG·MPG·M4V·MOV·WMV·AVI 영상을 먼저 고르고, 그런 파일이 없으면 이름순 첫 이미지(BMP·PNG·JPEG·GIF)를 기본 BGA로 사용합니다. 영상은 Windows Media Foundation 코덱으로 재생하며 GIF 내부 프레임 애니메이션은 아직 지원하지 않습니다. `#STP`, 잘못된 채보 데이터, 지원하지 않는 롱노트 방식, 명시적으로 정의한 샘플 파일을 찾을 수 없으면 실행을 막습니다. 보이지 않는 노트 채널은 모드 판별에 반영하고 플레이 레인에서는 그리지 않습니다.
- 곡 파일 난이도 전환에는 `Assets/levelchange.mp3`, 버튼·설정·목록 상호작용에는 `Assets/click.mp3`를 재생합니다. 효과음은 하나의 채널을 공유하며 요청이 겹치면 가장 마지막 요청만 재생하고, 재생 중 새 요청이 오면 다음 오디오 버퍼부터 앞선 효과음을 교체합니다. 설정의 효과음 볼륨으로 조절할 수 있습니다.
- 곡 선택 화면은 장르(`#GENRE`), 큰 곡 제목, 작곡가, BPM, `[레벨]`, 긴 START 버튼 순서로 표시합니다. START 클릭이나 Enter로 재생합니다. 왼쪽 하단의 5개 슬롯 중 첫 3개는 배속·판정 난도·게이지 모드 바로가기이며, 왼쪽 클릭은 증가, 오른쪽 클릭은 감소입니다. 배속은 0.25x 단위로 0.50x–10.00x, 판정은 BASIC→EASY→NORMAL→HARD, 게이지는 EASY→NORMAL→HARD 순서로 조절합니다. 나머지 2개 슬롯은 비워 둡니다.
- 곡 선택의 제목은 80px, 장르·작곡가·BPM은 30px로 이전의 2배 크기를 사용합니다. 설정창 배경은 검정이며, 카테고리와 하단 상태/닫기 버튼을 고정하고 내용만 별도 영역에서 스크롤합니다.
- 기타 설정의 곡 선택 배경은 회색(기본), 선택 곡의 BGA, 타이틀 이미지, 사용자 이미지 중 선택합니다. 블러 강도와 이미지 불투명도는 각각 0–100%입니다. 사용자 이미지는 실행 파일 옆 `Assets/browse-background.*`에 복사하고 복사본 파일 이름만 저장하므로 원본을 옮겨도 다시 실행할 때 그대로 표시합니다. BGA/이미지가 없으면 회색 배경을 사용합니다.
- 사운드 설정에서 **곡 하이라이트 부분 미리보기**를 켜고 별도의 미리보기 음악 볼륨(0–100%, 마스터 볼륨 적용)을 조절할 수 있습니다. `#PREVIEW` 지정 파일을 우선하고 같은 이름의 다른 확장자, 곡 폴더의 `preview*`·`_preview*` 및 `highlight`·`demo`·`trailer` 음원을 탐색합니다. WAV/OGG/MP3/FLAC/M4A/AAC/WMA/OPUS/AIFF/AIF를 탐색하며 실제 디코딩은 내장 Vorbis 또는 설치된 Windows 디코더를 사용합니다. 따옴표·하위 폴더·대소문자 차이를 처리하고, 재생할 수 없는 후보는 다음 음원으로 넘어갑니다. 전용 미리보기 음원은 파일 처음부터 전체 길이를 반복합니다. 모두 실패하거나 없으면 채보 BGM과 키음을 자동 재생하며, 일부 손상된 샘플은 미리보기에서만 건너뜁니다.
- 이 플레이어는 초 단위 확장 헤더 `#PREVIEWSTART` 또는 `#PREVIEWPOINT`, 선택적 `#PREVIEWDURATION`을 읽습니다. 시작 정보가 없으면 곡 검색 중 노트 분포와 곡 내 위치를 분석하여 자동 하이라이트를 선택하며 BGA도 같은 위치를 사용합니다. 지정된 0초는 그대로 유지하고, 짧은 곡·입력 노트가 없는 곡은 처음부터 재생합니다. 자동 재생은 기본 20초 구간을 반복합니다. 자동 선택은 [Qwilight의 노트 분포 기반 하이라이트 처리](https://github.com/thenist/Qwilight/blob/master/Qwilight/Compiler/BaseCompiler.cs)처럼 시작 명령이나 전용 파일이 없는 곡에도 동작합니다.
- 라이브러리를 불러오면 같은 곡 묶음의 시작 위치·미리보기 길이를 통일합니다. 유효한 명시적 시작 정보가 있으면 그 채보를 대표로 사용하고, 없으면 가장 낮은 레벨의 대표 채보를 사용합니다. 이후 한 작업자가 곡 묶음별 음원을 순차적으로 미리 디코딩하며 선택한 미완료 곡 요청은 대기 작업보다 우선합니다. 준비된 곡은 선택 후 0.5초가 지나면 캐시에서 재생하고, 같은 묶음의 난이도 전환은 음악을 끊거나 다시 시작하지 않습니다. 캐시 준비 여부와 관계없이 새 곡 선택 후 0.5초를 기다립니다. 최근 음원 캐시는 최대 64개·256MiB를 기준으로 오래된 항목부터 비우며 현재 선택 항목은 보호합니다. 곡 폴더 재검색은 이전 캐시를 폐기합니다. 인게임 진입 시 미리보기 캐시와 대기 작업을 해제하고 목록 복귀 후 선택 곡을 다시 준비합니다.
- 사운드 설정에서 출력 버퍼를 32 / 64 / 128 / 256 / 512 / 1024 샘플 프레임 중 선택할 수 있습니다. 기본값은 256이며, 변경 시 대기 화면 효과음 출력을 다시 시작하고 이후 곡 재생에도 동일하게 적용합니다. 선택값은 믹서 처리 블록 크기이며, WASAPI 이벤트 출력의 실제 주기는 장치의 최소 주기와 공유 엔진 제한에 맞춥니다. 음원은 장치 샘플 레이트에 맞춰 사전 디코딩합니다. 음성별 연속 샘플 구간을 믹싱하고 볼륨은 블록마다 한 번 읽으며, 오디오 스레드는 MMCSS Pro Audio 우선순위를 사용합니다.
- 게임플레이 설정에서 NORMAL / EASY / HARD 그루브 게이지를 선택할 수 있습니다. NORMAL과 EASY는 20%에서 시작해 노트 수 N에 따라 `a = 200/N`만큼 PGREAT·GREAT 시 증가하고 GOOD은 절반 증가합니다. BAD·POOR 감소량은 각각 NORMAL `-2%/-6%`, EASY `-1.6%/-4.8%`입니다. 두 모드는 게이지로 게임오버되지 않으며 종료 시 80% 이상이면 클리어 조건을 충족합니다. HARD는 100% 시작, PGREAT·GREAT `+0.16%`, GOOD 변화 없음, BAD `-5%`, POOR `-9%`이며 0%에 도달하면 즉시 실패합니다. 리절트에는 조건에 따라 CLEAR / NO CLEAR / FAILED를 표시합니다.
- 곡을 시작하면 채보와 음원을 백그라운드에서 준비하는 동안 `#STAGEFILE` 또는 같은 폴더의 `title.*` / `stagefile.*` 이미지를 선택 화면 위에 페이드 인으로 표시합니다. 준비가 끝나면 짧은 페이드 아웃 후 음악과 채보가 바로 시작됩니다. 결과 화면은 `#BACKBMP`나 같은 폴더의 `finish.*`, `result.*` 이미지를 배경으로 사용하며, 결과 이미지가 없으면 타이틀 이미지로 대체합니다. 이 이미지 후보는 기본 BGA 자동 선택에서 제외됩니다.
- 곡 목록은 영문 제목 A–Z, 한글 제목 ㄱ–ㅎ, 그 외 문자 순서로 나누며 한글은 한국어 정렬 규칙을 사용합니다.
- 판정 문구·게이지·점수·리절트는 프로토타입 기준이며 IIDX 판정이나 게이지를 재현하지 않습니다. 컨트롤러 입력, 자동 플레이 및 랜덤·미러 옵션은 포함하지 않습니다.

## 자동 테스트

`BmsCoreTests`는 임시 WAV와 UTF-8·Shift-JIS 채보를 생성해 7+1키 레인과 스크래치, 동시 타임라인, BPM 변경, 마디 길이, STOP, `LNOBJ`와 `LNTYPE 1`, 조건 분기, 5키·10키·14키·PMS 모드 판별, 미지원 롱노트 형식, 잘못된 데이터와 누락 음원을 확인합니다. `BmsAudioTests`도 실행 중 짧은 WAV 음원을 만들어 Windows Media Foundation 디코딩을 확인합니다.

`BmsJudgementTests`는 양쪽 방향의 PGREAT·GREAT·GOOD·BAD·POOR 경계를 검사합니다. `BmsLongNoteTests`는 지속 홀드와 꼬리 판정 ±116.67ms 구간의 PGREAT·POOR·BAD 경계를 검사합니다.

`BmsFrameTests`는 고정 FPS 타이머 간격을 실제로 측정하고, 거친 오디오 위치값을 입력해 보간·단조 증가·출력 정지·재시작을 확인합니다. `BmsUiTests`는 별도 설정 파일로 앱을 띄워 목록·버튼에서 Space로 설정창 열기, 버튼 이동, FPS 선택, 8개 색상 선택, Space를 포함한 키 변경, 중복 키와 취소, 재시작 후 저장값 복원을 검사합니다. `Validation/settings.bmp`에 실제 설정창을 캡처합니다. 실제 모니터의 고주사율 출력 및 체감 지연은 별도로 플레이하며 확인해야 합니다.

`BmsLongNoteTests`는 10초 홀딩 동안 몸체 상태 유지, 0.5x·1x·5x 화면 범위, 시작 시각이 오래 지난 롱노트, 이른 해제와 재입력, 끝 시각의 정상 완료, 스크래치·다른 레인의 독립적인 홀딩, 재시작 초기화를 검증합니다.

`BmsBgaTests`는 원본 색상, 독립적인 예상값을 가진 부드러운 확대, 투명도, 자르기 위치, 화면 밖 자르기, 누락 이미지, 음영 범위, 캐시 재사용, 크기 변경 및 곡 초기화를 검사합니다.

성능 진단은 배포 앱에서 비활성화됩니다. `cmake --build build --config Release --target BmsPlayerProfile BmsRenderTests`로 별도 진단 도구를 빌드할 수 있습니다. `BmsPlayerProfile.exe`에서 실제 곡을 재생하면 실행 파일 옆의 `BmsPlayer-performance.csv`에 프레임별 오디오 위치 조회·BGA·HUD·노트·출력 비용을 기록합니다. `BmsRenderTests.exe "채보 경로" "기록.csv" [배속] [시작 초]`는 실제 렌더 함수를 사용해 해당 채보 구간의 BGA 및 노트를 240회 반복 그립니다.
