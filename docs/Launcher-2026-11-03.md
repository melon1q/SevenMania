# SevenMania Launcher 구현 보고서

## 구현 범위

요구사항의 범위 조정 조항에 따라 **공유 설정, 독립 런처, 비디오/BGA 설정, 외부 곡 등록·캐시, 게임 실행 연동**을 우선 구현했다. 전체 11개 Phase가 모두 완성된 것은 아니다. 스킨 선택, 오디오 장치 선택, 화면별 FPS 등 미구현 기능은 아래에 분리했다. 해당 탭에도 지원하지 않는다고 명시했으며 작동하지 않는 설정 입력창을 제공하지 않는다.

Release 폴더에 다음 파일을 생성했다.

- `SevenManiaLauncher.exe`: 독립 Win32 GUI 런처
- `SevenMania.exe`: 기존 게임 타깃의 동일 바이너리를 배포 이름으로 복사
- `BmsPlayer.exe`: 기존 기본 실행 파일도 계속 업데이트

게임은 런처의 IPC나 실행 상태에 의존하지 않는다. 런처는 절대 경로의 `SevenMania.exe`를 `CreateProcessW`로 실행하고 작업 디렉터리를 실행 파일 폴더로 지정한다. 실행 파일 이름을 명시하며 인용한 UTF-16 명령줄을 전달한다. 런처 종료 시 프로세스 핸들만 닫으며 게임을 종료하지 않는다.

## 기존 코드 조사

- `Main.cpp::wWinMain`: 설정 경로 → 라이브러리/기록 → 그래픽/오디오·UI 초기화 → 창 생성/화면 모드 적용 → 캐시 기반 선곡 로딩.
- 기존 기본 설정 파일은 `%APPDATA%/BmsPlayer/keybindings.ini`. `BMS_PLAYER_CONFIG_PATH` 절대 경로 override와 별도 진단 빌드 설정 파일도 존재한다.
- `loadDisplaySettings`/`saveDisplaySettings`, `SettingsController`, `SettingsRmlPage.inl`이 게임의 기존 설정 경로다. 런처 전용 별도 설정 저장소를 만들지 않았다.
- `FrameRateSettings.h`의 FPS 값은 60/144/240/400/0/-1이다. 0은 최대 1500FPS, -1은 기존 VSync 모드다. FramePacer는 VSync 모드의 업데이트 루프도 제한하며 실제 Present의 동기화와 기존 연동을 유지한다.
- 해상도/전체화면은 `availableResolutions`/`applyScreenMode`와 현재 창의 모니터를 사용한다. DXGI 독점 모드를 새로 가정하거나 추가하지 않았다.
- BGA 출력은 기존 `Display/Brightness`와 관련 렌더링 분기로 제어한다. 0이면 출력 OFF다.
- `AudioEngine`은 WASAPI 공유 모드의 Windows 기본 출력 장치와 기존 버퍼 요청값을 사용한다. 사용자 장치 ID를 선택하는 기존 설정은 없다.
- 외부 스킨은 기존 `Skin/PackagePath`와 스킨 호스트가 처리한다. 런처에서 이 형식을 바꾸지 않는다.
- SongLibrary/SongMetadataCache/SongLibrarySources의 기존 메타데이터 및 루트 관리를 그대로 사용한다. ROOT 표시 정책, 곡 그룹, 기록 키는 변경하지 않았다.

## 공유 설정과 충돌 정책

`src/SharedStartupSettings.h`에 경로 결정, 초기 설정 정규화, 설정/캐시 작업 배제, 원자적 런처 저장, 시작 모니터 배치를 분리했다.

- 기존 APPDATA 경로를 그대로 읽는다. APPDATA가 없으면 실행 파일 옆 `Config/keybindings.ini`를 대체 경로로 사용한다. 절대 경로 환경변수 override는 우선한다.
- FPS/화면 모드/해상도/밝기/버퍼를 게임과 런처가 동일한 정규화 함수로 읽는다. 누락·잘못된 값은 기존 기본값/범위로 처리하며, 구형 BGADarkness도 읽는다.
- 런처 저장은 최신 INI를 같은 디렉터리의 임시 파일로 복사하고 **사용자가 변경한 키만** 갱신한 뒤 Flush 및 MoveFileEx 원자적 교체를 수행한다. 알려지지 않은 키, 입력/스킨/기록 관련 설정을 보존한다.
- 같은 항목이 창을 연 이후 다른 런처에서 변경되면 저장을 거부한다. 다른 항목의 변경은 보존하고, 저장 후 UI도 최신 값으로 동기화한다. 외부 루트 목록도 충돌을 검사한다.
- 게임은 공유 설정 경로로 식별한 named mutex를 실행 동안 소유한다. 같은 설정을 사용하는 다른 게임은 시작을 거부한다. 런처는 게임 실행 중 저장/캐시 갱신을 거부하며 게임 종료 후 다시 적용할 수 있다. 런처 인덱싱도 이 mutex를 소유하므로 동시에 시작한 게임은 작업이 끝난 후 재시도해야 한다.
- 게임 시작 버튼은 우선 변경 사항을 저장하고 성공한 경우에만 게임을 실행한다. 저장 충돌/실패를 무시하고 시작하지 않는다.
- 런처에서 시작한 게임의 프로세스 핸들도 확인해 같은 창에서 중복 시작을 거부한다. 프로세스 시작 직후 경합이 있어도 게임의 mutex가 중복 실행을 차단한다.
- `[SevenMania] SettingsVersion=1`을 기록한다. 기존 게임 저장 방식은 유지하며 게임의 모든 쓰기를 원자적 트랜잭션으로 바꾼 것은 아니다. 게임/런처 사이의 동시 쓰기는 실행 배제로 방지한다.

숫자·누락 항목의 안전한 기본값 처리는 구현했지만 완전히 깨진 설정 파일의 자동 백업·복구 UI는 미구현이다. 동일 설정 경로를 사용하지 않는 별도 프로필이나 기존 CLI 도구까지 아우르는 전역 캐시 잠금은 제공하지 않는다.

## 실제 연동 항목

| 런처 항목 | 기존 엔진 설정/동작 |
|---|---|
| 모니터 | `Display/Monitor`, 게임 창을 해당 모니터에 배치한 후 기존 화면 모드 적용 |
| 해상도 | `Display/ResolutionWidth`, `ResolutionHeight` |
| 화면 모드 | `Display/ScreenMode` 0/1/2 |
| 최대 FPS / VSync | 기존 `Display/FPS`, `FrameRateSettings.h` 값과 의미 유지 |
| BGA 출력 | `Display/Brightness` 0 또는 기존 양수 밝기; OFF 후 다시 켜면 기존 값이 없을 때 50 |
| 오디오 버퍼 | 기존 `Sound/BufferFrames` 32/64/128/256/512/1024 |
| 외부 곡 등록 | 기존 `[SongLibrarySources]`, 같은 UTF-16 경로 인코딩 |

모니터와 해상도는 Windows API로 조사한다. 해상도는 기존 게임과 동일하게 현재 모니터 크기 이하의 실제 열거 모드로 제한하며, 유효하지 않은 선택은 자동 값으로 복구한다. G-Sync/VRR 지원 자동 판정이나 새로운 VSync/FPS 중복 대기를 추가하지 않았다. 모니터·화면 모드·BGA·버퍼는 다음 게임 시작에 적용된다.

런처의 FPS는 기존 플레이 설정이다. 곡 선택/플레이/리절트별 독립 FPS는 아직 연결하지 않았으며 그런 값을 저장하는 가짜 옵션도 만들지 않았다.

## 라이브러리·캐시

기본 Songs 자동 등록, 외부 폴더 여러 개 추가/해제, 연결 상태 표시, 선택 루트 재검색, 전체 증분 갱신을 제공한다. 파일은 복사/이동/삭제하지 않는다. 기존 실제 경로 정규화·중첩 루트 처리·중복 제거를 사용한다.

인덱싱은 취소 가능한 worker에서 실행하고 완료 결과를 UI 메시지로 전달한다. 재검색/전체 갱신 버튼을 다시 누르면 취소한다. 완료 시 채보 수와 오류/경고 개수를 표시한다. 오류/경고에는 스캔 경고와 플레이 불가능 채보가 포함되므로 순수 파싱 오류 수와 동일하지 않다. 곡 그룹 수 표시는 미구현이다. 진행 중 상태는 표시하지만 파일별 백분율은 제공하지 않는다.

캐시 위치와 버전은 게임과 동일하다. 변경되지 않은 채보는 기존 캐시를 재사용한다. 기존 스캐너의 캐시 미스 분석은 원래 BMS 파서를 거친 뒤 메타데이터만 남긴다. 헤더 전용 파서를 새로 구현한 것은 아니다. BGA 영상·키음 디코딩, 게임 GPU 텍스처 생성, 오디오 장치 초기화는 런처에서 수행하지 않는다.

## GUI 및 의존성

Win32 common controls를 선택했다. 기존 C++/CMake로 빌드되며 별도 .NET·웹뷰·브라우저 런타임 없이 동작한다. 회색 기본 컨트롤과 시스템 글꼴로 구성했다. 고급 금속 질감의 커스텀 UI를 제작한 것은 아니다.

비디오/오디오/스킨/곡 라이브러리/고급 탭, 적용·게임 시작·화면/버퍼 초기화 버튼을 제공한다. 시스템 DPI에 맞춘 좌표·글꼴 크기 조정, 작은 높이에서의 세로 스크롤, 기본 키보드 탭 탐색을 구현했다. 라이브러리 목록은 긴 경로 확인을 위한 가로 스크롤을 제공한다. 실제 다중 DPI 장치 간 이동 검증은 하지 않았다.

실제 `dumpbin /DEPENDENTS`에서 런처는 COMCTL32/SHELL32/ole32/KERNEL32/USER32/GDI32 및 Windows 동기화 API만 확인했다. MSVC 런타임은 기존 프로젝트의 정적 링크 정책을 따른다. 런처 자체에 Assets는 필요하지 않지만 게임 배포에는 기존 Assets/UI·폰트·스킨·이미지·효과음 등이 필요하다. 게임의 Direct3D/D2D/Media Foundation 등 기존 Windows 의존성도 유지된다. 기본 스킨이나 RmlUi 에셋을 수정하지 않았다.

## 빌드·실행·테스트

Release 빌드 성공. 기본 BmsPlayer.exe와 SevenMania.exe의 크기는 각각 5,571,584 bytes이며 같은 게임 바이너리다. 런처는 약 1MB이고, 최종 크기는 파일 속성을 기준으로 확인할 수 있다.

관련 CTest **11/11 통과**:

- SevenManiaLauncherTests
- SevenManiaLauncherUiTests
- SevenManiaStartupIntegrationTests
- BmsLibraryTests, BmsSongSelectionTests, BmsSongLibraryUiTests
- SevenManiaSkinBindingTests, SevenManiaSkinApplicationTests
- BmsSettingsPhase6Tests, BmsFrameTests, BmsLowLatencyTests

실제 런처 창의 적용/전체 갱신/게임 시작 명령 경로를 자동 실행했다. 한글·일본어·공백이 있는 격리 배포 경로에 실제 게임과 Assets를 복사해 SevenMania.exe를 실행했고, 런처 창 종료 후 게임 생존도 확인했다. 테스트 게임만 기존 종료 확인창에 정상 응답해 종료했다. 기존 사용자 게임 프로세스는 종료하지 않았다.

| 요구 검증 | 결과/한계 |
|---|---|
| 게임 단독 실행 경로 | 런처 전용 인자·IPC 없이 실제 게임 프로세스 초기화 성공. 기본 APPDATA 사용 수동 실행은 별도 미검증 |
| 런처 → 게임 / 런처 종료 후 게임 유지 | 실제 프로세스로 통과 |
| 설정 저장·재로드·구형 설정·유니코드 | 기본값/구형 어둡기/알 수 없는 키 보존·원자적 롤백·재로드 통과 |
| 해상도·모드·FPS·VSync | 실제 게임의 loadDisplaySettings 전역값 적용 확인. 실제 화면 전환·Present 동기화 실측은 미검증 |
| BGA OFF | GUI 저장 및 실제 게임 로더에서 밝기 0 확인. 실제 플레이 영상 캡처는 미검증 |
| 오디오 | 실제 게임 버퍼 값 연결 확인. 장치 선택은 미구현, 실제 장치 지연 실측은 미검증 |
| 스킨 | 기존 설정 보존 및 기존 적용/바인딩 회귀 통과. 런처 선택 기능은 미구현 |
| 외부 등록·해제·캐시 공유 | 원본 보존, worker 완료, 게임용 snapshot으로 캐시 재사용 확인 |
| 설정 충돌 | 게임 실행 중 저장 차단, 같은 키 충돌 거부, 관련 없는 변경 병합 및 GUI 재동기화 통과 |
| 캐시 손상·잘못된 외부 경로 | 기존 LibraryTests의 손상 복구·경고/취소 검사 통과 |
| 기록·기존 설정 UI | 기존 격리 기록/스킨 및 Phase6 설정 UI 회귀 통과 |

로그는 `build-rmlui-song-list/Validation/launcher-*.log`, 격리 UI/게임 실행 결과는 `Validation/LauncherUI/`에 있다. 실제 런처 비디오 탭 캡처도 이 경로에 저장해 확인했다. 빌드 파일/임시 배포/캐시/캡처는 커밋에 포함하지 않는다. 이전의 곡 목록 Host 픽셀 검사 문제를 해결하거나 전체 프로젝트의 모든 테스트가 통과했다고 주장하지 않는다.

## 남은 기능

1. 런처 스킨 목록·선택·형식 검증·미리보기, 기존 에디터 실행 연결
2. 오디오 출력 장치 선택과 분리/재연결 대응; 기존 엔진에는 기본 장치만 선택하는 코드가 있어 별도 실제 연동 필요
3. 곡 선택/플레이/리절트별 FPS 및 실게임 프레임 타임 비교
4. BGA OFF에서 초기 불필요 디코딩까지 생략하는 별도 최적화. 현재는 기존 밝기 0 경로를 사용
5. 고급 DPI/키보드 접근성·여러 실제 모니터 모드 전환·장치 환경의 수동 검증
6. 완전히 손상된 설정의 백업/복구 UI, 다른 설정 파일/CLI 작업까지 포함하는 캐시 작업 배제

이 범위는 실제 구현되지 않았으며 이후 개발 대상으로 남겼다.
