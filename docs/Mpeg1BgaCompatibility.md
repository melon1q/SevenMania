# MPEG-1 BGA 호환 수정

## 재현 및 원인

`B.B.K.K.B.K.K.`의 `01.mpg`를 기존 `BmsVideoTests`에 전달하면
`real video reader could not open media` 오류로 실패했다.
`_n.bms`와 `_a.bms`에는 `#BMP01 01.mpg`, `#00104:01` 참조가 있었다.
파일은 MPEG-1 영상 전용 스트림이며 256×256, 30fps, 4051프레임이다.
현재 환경에서 Media Foundation Source Reader로 이 스트림을 열지 못했다.
파일 확장자를 바꾸거나 원본을 변환하지 않고 디코더 보완으로 해결했다.

## 변경

- 기존 Media Foundation 경로가 파일 열기에 실패하면 MPEG-1 보조 리더를 사용한다.
- `Mpeg1Video`는 pl_mpeg의 영상 전용 API를 이용한다. 새로운 외부 프로세스,
  사용자 코덱 설치, FFmpeg 실행은 필요하지 않다. MIT 라이선스 고지를 배포에 포함한다.
- Windows 파일 API로 한글·일본어 경로를 열고, 기존 비동기 영상 워커에서 디코딩한다.
- 기존 BGA 이벤트 시계, 레이어, BGRA 프레임·스케일러·렌더링 경로를 재사용한다.
  원본 곡 파일, 스킨 디자인, 판정 및 오디오 엔진은 변경하지 않는다.
- 첫 4KiB에서 MPEG 시퀀스 헤더를 확인한다. 해상도는 짝수 2~2048,
  파일은 512MiB 이하로 제한하며 MPEG-2 시퀀스 확장을 거부한다.
- 현재 보조 리더 범위는 MPEG-1 elementary stream이다. MPEG-2 및 MPEG-PS의
  새 디코더 지원을 의미하지 않는다. 그 형식들은 기존 Windows 경로를 사용한다.
- 파일과 디코더 버퍼는 리더 해제 시 반환한다. 반복 열기·되감기를 검증했다.
- 전방 탐색은 필요한 중간 프레임을 영상 워커에서 순차 디코딩한다. 별도 키프레임
  인덱스는 이번 수정에 추가하지 않았다.

## 검증

- 기본 `BmsPlayer.exe` Release 빌드 성공.
- 소형 원본 MPEG-1 색상 테스트 영상으로 첫 프레임, BGRA 색상/알파,
  시간 진행, 초기 탐색, EOF 반복, 되감기, 한글 경로, 반복 열기 및 잘못된 헤더 확인.
- 기존 AVI 첫 프레임·타임스탬프·레이어·동시 영상·재시작 회귀 테스트 통과.
- 실제 `01.mpg`의 첫 프레임 준비 약 5ms. 실제 영상의 10·65·120·134초 프레임
  시간이 요청과 50ms 미만 차이로 일치했고, 되감은 첫 프레임이 최초 프레임과 같았다.
- 실제 `_n.bms`의 BGA 시작 1.41176초, 시작 전 비표시 및 시작 후 진행·재시작 확인.
- 실물 곡 파일은 읽기 전용으로 사용했으며 테스트 데이터나 Git에 포함하지 않았다.
- 게임 창을 통한 수동 플레이 화면 검증은 실시하지 않았다.
