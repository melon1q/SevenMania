# 곡 복사본과 빠른 채보 검색

외부 곡 폴더를 선택하면 실행 파일 옆의 `Songs/<원본 폴더명>-<경로 식별자>`에 모든 파일과 하위 폴더를 복사한다. 채보뿐 아니라 음원, BGA, 이미지, 부속 파일과 빈 폴더도 보존한다. 동일한 이름의 서로 다른 원본 폴더는 경로 식별자가 달라 서로 덮어쓰지 않는다.

복사본의 경로를 마지막 곡 폴더로 저장하므로 재실행 시 복사본에서 곡 목록을 검색한다. 원본이 이동되거나 삭제되어도 복사된 곡을 사용할 수 있다. 이미 `Songs` 안에 있는 폴더를 선택하면 추가 복사가 필요하지 않다.

같은 외부 폴더를 다시 선택하면 기존 복사본을 갱신한다. 파일 크기와 수정 시간이 같은 파일은 건너뛰고 새 파일과 변경된 파일만 복사한다. 복사본에서 별도로 보관한 파일은 자동 삭제하지 않는다. 원본을 수정할 때 크기와 수정 시간을 모두 이전 값으로 유지하면 변경을 감지할 수 없으므로 수정 시간을 갱신해야 한다.

복사와 분석은 백그라운드에서 실행되며 상태줄에 진행률을 표시한다. Esc로 취소할 수 있다. 새 복사본은 임시 폴더에서 완성한 다음 등록하고, 실패하거나 취소하면 그 임시 폴더를 정리한다. 기존 복사본을 갱신할 때는 각 파일을 임시 파일로 복사한 다음 교체한다. 취소 전 완료된 갱신 파일은 유지한다. 복사 실패 시 해당 경로를 상태줄에 표시하며 마지막으로 저장한 곡 폴더는 변경하지 않는다.

`Songs`를 포함하는 상위 폴더를 원본으로 선택하는 재귀 복사는 차단한다. 곡 폴더 안의 링크 파일이나 연결된 폴더도 복사 오류로 알린다. 실행 파일이 있는 폴더에 쓰기 권한과 곡 파일을 저장할 공간이 필요하다.

## 분석 최적화

- 채보 파일을 바이트 단위 반복문 대신 한 번의 버퍼 읽기로 불러온다.
- 폴더의 파일 목록을 한 번 읽어 음원의 존재 여부, WAV/OGG/MP3 대체 파일과 BGA 후보를 찾는다.
- 빠진 WAV 정의가 있을 때만 형제 채보의 정의를 읽고, 같은 곡 폴더의 나머지 채보에도 재사용한다. 현재 채보의 비활성 분기 정의를 자기 자신에게서 가져오지는 않는다.
- 서로 다른 곡 폴더를 최대 4개의 작업 스레드로 분석한다. 같은 곡 폴더는 한 파서로 처리해 파일 목록과 정의를 공유한다.
- 매 검색마다 캐시를 새로 만들며 재생 진입에서도 다시 분석한다. 외부 파일 변경, 누락 음원과 모드 차단 검사가 오래된 캐시에 가려지지 않는다.

## Windows 검증

2026-10-11 Release 빌드에서 기존 파서와 변경된 폴더 검색기를 번갈아 3회씩 실행한 중앙값이다. 동일한 실제 곡 폴더를 읽었으며 폴더 복사 및 음원 디코딩 시간은 포함하지 않는다.

| 곡 폴더 | 채보 / 노트 / 플레이 가능 | 기존 분석 | 변경 후 분석 |
| --- | --- | --- | --- |
| Cat's_rule | 9 / 6,407 / 4 | 2,763.65ms | 417.17ms |
| slic_hertz | 5 / 4,921 / 4 | 546.48ms | 46.88ms |

채보 수, 노트 수와 플레이 가능 수는 변경 전후 동일했다. 실제 대기 시간은 저장 장치와 폴더 크기에 따라 달라지며 첫 복사에는 미디어 전체를 저장하는 시간이 추가된다.

라이브러리 테스트는 한글·아포스트로피 경로, 전체 미디어 복사, 빈 폴더, 변경 파일 갱신, 동일한 폴더명 충돌 방지, 취소 정리, 원본 삭제 후 사용, 병렬 검색과 기존 단일 파서의 결과 일치를 확인한다. UI 테스트는 실행 파일 옆 복사본 경로 저장, 원본 삭제 후 앱 재실행과 실제 오디오 재생을 확인한다.
