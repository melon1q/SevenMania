# 영상 BGA 확대 중복 작업 제거 (2026-10-30)

두 번째 개선 대상은 영상 BGA의 CPU 확대 경로다. VideoFrameScaler를 추가하고 각 AsyncVideoBga 디코더 작업 스레드가 전용 인스턴스를 유지한다.

- 원본 프레임을 임시 Image 벡터에 통째로 복사하던 작업을 제거했다. 입력을 직접 읽으며 공개된 영상 프레임을 수정하지 않는다.
- 입력/출력 크기가 유지되는 동안 X/Y 보간 좌표표와 두 개의 작업 행 버퍼를 재사용한다.
- 원본과 출력 크기가 같으면 보간을 생략하고 최종 출력으로 한 번만 복사한다.
- BgaRaster::scaleVideoFrame의 기존 호출 인터페이스는 유지한다. 이 호환 호출은 로컬 scaler를 사용하며, 영상 디코더 경로만 지속적인 작업 공간을 유지한다.

1080p 입력에서는 확대를 수행할 때마다 원본 8,294,400바이트의 임시 복사본 생성이 사라진다. 이는 구조상 제거한 복사량이며 측정된 FPS 개선률이 아니다. 출력 프레임 버퍼의 할당/복사는 유지한다. UI가 보유 중인 과거 프레임을 덮어쓰지 않기 위해 출력 버퍼를 작업 공간과 공유하지 않는다. GPU 확대·합성 및 하드웨어 디코딩 전환은 후속 작업이다.

검증:

- 독립적인 4탭 기준 보간과 픽셀 전체 비교: 확대/축소, 동일 크기, 1픽셀 축, 비정수 배율 및 알파 포함 입력.
- 같은 scaler의 크기 변경·반복 호출, 입력과 출력이 동일 벡터인 경우, 잘못된 크기/입력 길이/메모리 상한 검사.
- 1080p 입력의 축소 및 동일 크기 출력에서 준비된 출력 버퍼를 사용하면 추가 C++ 할당 0회임을 검사. 실제 디코더의 새 출력 프레임 할당까지 0이라는 의미는 아니다.
- 기존 영상 첫 프레임/시계/seek/재시작/취소, BGA 및 화면·스킨 회귀 검증.

기본 배포 실행 파일은 build-rmlui-song-list/Release/BmsPlayer.exe이며 빌드 후 사용자 배포 스킨을 복원한다.
