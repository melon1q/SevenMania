# 컨트롤러 입력

설정 → 게임 플레이 → **컨트롤러 입력 설정...**에서 사용한다. 기존 키보드 설정과 함께 사용할 수 있다. 최초 기본값은 꺼짐이며, 저장하면 다음 실행에도 유지된다.

## 연결 및 배치

1. USB 컨트롤러를 Windows가 게임 컨트롤러로 인식하는 모드로 연결한다. IIDX 전용 컨트롤러의 게임패드/HID 모드는 제조사 설명서에 따라 선택한다. 키보드 모드는 기존 키 배치 설정으로 사용한다. PS2 단자 제품은 Windows 게임 컨트롤러로 인식되는 별도 어댑터가 필요하다.
2. 설정 창에서 장치를 선택한다. 아래 입력 확인 영역에 버튼 번호와 축 값이 표시된다. 연결 후 나타나지 않으면 **다시 검색**한다.
3. 건반 1~7과 스크래치 버튼을 실제 번호에 맞춘다. 번호는 1부터이며, 사용하지 않는 항목은 끌 수 있다. 스크래치의 양방향 버튼은 같은 스크래치 레인으로 합쳐진다.
4. 턴테이블이 축으로 인식되면 움직이는 축을 선택한다. 계속 회전하는 장치는 **턴테이블 회전축**, 손을 놓으면 중앙으로 돌아오는 장치는 **중앙 복귀 축**을 선택한다. 버튼만 사용하는 장치는 축 동작을 **버튼만 사용**으로 정한다.
5. 저장하고 플레이에서 확인한다. **시작 / 일시정지** 버튼은 플레이 중 일시정지·재개에 사용한다. 곡 선택 화면 탐색과 시작은 기존 키보드를 사용한다.

축 값은 0~65535 범위다. 회전축은 경계를 넘어가는 회전을 처리하고, 누적 움직임이 감도를 넘을 때 스크래치를 발생시킨다. 감도 숫자가 작을수록 작은 움직임에 반응한다. 스크래치 유지는 마지막 유효 움직임 이후 누르고 있을 시간이다. 기본값은 감도 256, 유지 80ms이며 장치에 맞게 조정한다. 중앙 복귀 축은 중앙 32767에서 감도 이상 벗어나 있는 동안 눌림이다.

## 동작과 범위

- DirectInput 8로 Windows 게임 컨트롤러의 버튼 최대 128개와 축 8개를 읽는다. 이번 연결 범위는 1P 7+1 레인이다. 전용 드라이버나 제조사 전용 통신만 제공하는 장치의 호환성까지 보장하지 않는다.
- 프레임 처리와 별도 입력 타이머에서 버퍼링된 버튼 변화를 읽는다. 프레임 사이의 짧은 누름도 전달하되, 버퍼가 넘치면 최신 상태로 복구한다. Windows 스케줄링에 따른 지연은 있을 수 있다.
- 키보드와 컨트롤러가 같은 레인을 누르면 둘 다 놓아야 해제된다. 회전 중의 추가 스크래치는 기존 판정 입력을 이용하며, 진행 중인 롱노트를 강제로 다시 누르지 않는다.
- 포커스 상실·분리 시 입력을 해제하고 재연결 시 이미 눌린 버튼은 놓은 다음 다시 눌러야 한다. 게임 데이터는 기존 판정 경로로만 전달한다. 컨트롤러 창의 입력 확인은 판정을 발생시키지 않는다.
- `[Controller]` INI 구역에 활성화, 장치 ID, 버튼·축·감도·유지시간을 저장한다. 기존 키보드 및 게임 설정은 유지한다.
- 새 외부 라이브러리는 추가하지 않았다. Windows의 DirectInput 라이브러리를 사용한다.

자동 테스트는 매핑·회전 경계·포커스·분리·설정 창 저장/취소를 검증한다. 실물 IIDX 컨트롤러의 입력 지연과 기기별 매핑은 실제 장치에서 확인해야 한다.

## 이번 변경의 검증

- 판정 텍스트의 0px 기준은 기존 위치에서 추가로 50px 위로 이동했다. 사용자 설정 오프셋은 유지하며, 스킨 렌더러·기본 템플릿·기존 표시 경로·설정 미리보기에 반영했다.
- Release 기본 실행 파일 `build-rmlui-song-list/Release/BmsPlayer.exe`를 갱신했다.
- `BmsControllerTests`: 49개 검증 통과. 실제 Windows 설정 창을 생성해 저장·취소와 INI 재읽기를 확인했다.
- `BmsSettingsPhase5Tests`: 기존 입력 설정과 RmlUi에서 컨트롤러 설정 창 열기·취소·복귀 검증 통과.
- `SevenManiaSkinApplicationTests`: 기존 외부 스킨 적용·복구 등 100개 검증 통과.
- 실물 컨트롤러 플레이와 전체 곡 플레이는 자동 테스트에 포함하지 않았다.
