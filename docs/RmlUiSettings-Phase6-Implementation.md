# RmlUi 설정 6단계 완료 기록

2026-10-27 / `codex/rmlui-settings-ui-test`

사용자가 5단계까지 직접 테스트를 완료했다고 확인한 뒤 기본 활성화와 안정화 검사를 진행했다. 수동 확인을 자동 검사 결과로 바꾸어 서술하지 않는다.

## 기본 동작과 정리

- 설정을 열면 RmlUi 요약 페이지로 진입한다. 기존 임시 진입점인 기타 페이지에서 시작하지 않는다.
- 설정 UI 빌드 옵션의 기본값은 ON이다. 곡 목록 렌더러 선택과 독립적으로 설정 UI를 사용할 수 있다. 해당 기능을 끈 빌드에서는 네이티브 설정을 정상 경로로 사용하며 문서 로딩 실패로 취급하지 않는다.
- 하단 `기존 설정창 사용`과 카테고리별 기존 화면 열기를 유지한다. 실패 시 자동 복귀도 유지한다. 다음에 설정창을 다시 열면 RmlUi 기본 경로를 다시 시도한다.
- 게임플레이의 사용법 버튼도 기존 설명 명령에 연결했다. 수치 설정 Snapshot의 모든 ID가 새 화면 명령 표에 매핑되는지 검사한다.
- 닫기 전에 남은 설정 적용 요청을 처리한 후 실제 값을 저장한다. 슬라이더 변경 직후 곧바로 닫아도 마지막 값이 유실되지 않아야 한다.
- 미리보기 오버레이 HWND, DC, 비트맵과 픽셀 참조를 설정창 종료 시 해제한다. 게임 종료도 같은 정리 함수를 사용한다. 기존 Win32 설정 구현의 삭제나 `main` 병합은 수행하지 않았다.

## 검사 범위

`BmsSettingsPhase6Tests`를 추가했다. 합성 INI와 합성 곡을 사용하며 개인 설정·곡 파일을 변경하지 않는다.

| 항목 | 확인 방법 |
| --- | --- |
| 기본 경로 | 실제 `openSettings()`로 요약 페이지 진입 및 다음 세션 복구 |
| 허용 경로 | 곡 선택에서 열기, 플레이/일시정지 및 플레이 로딩 중 기존 열기 제한 유지 |
| 현재 INI | 마지막 변경 직후 닫기→재읽기, 모르는 섹션/키 보존 |
| 이전 INI | BGADarkness·DirectComposition 호환 읽기→저장→재읽기, 모르는 키 보존 |
| 전체 설정 연결 | Snapshot에 포함된 모든 설정 ID의 새 UI 바인딩 존재 검사 |
| 자원 수명 | 32회 개폐 및 매회 5개 카테고리 그리기, 미리보기 버퍼 생성·해제 |
| 숨긴/닫힌 화면 | 숨긴 화면 타이머에서 렌더 프레임 수 불변, 종료 후 HWND·미리보기 자원 없음 |
| 호환 화면 | 네이티브 전환, 재열기, UI 옵션 OFF 정상 진입 |

RML/RCSS 누락·잘못된 문서·세션 오류 복구는 Phase3, 물리 키·중복·키 해제 대기·취소·미리보기·장치 전환은 Phase5, 작은 창·DPI 메시지·드롭다운·스크롤은 Phase3 및 입력 호스트 테스트에서 함께 검사한다. 실제 곡 재생·화면 모드·장비별 Reflex 등의 수동 확인은 사용자의 테스트 완료 보고를 근거로 기록한다. 자동 검사는 소리의 출력 품질이나 모든 물리 장비의 동작을 보장하지 않는다.

결과: 기본 ON 구성의 관련 테스트 9개 통과. 설정 ON/곡 목록 RmlUi OFF 구성은 Phase6, 설정 OFF/곡 목록 RmlUi ON 구성과 RmlUi 전체 OFF 구성은 기존 설정 기준 테스트를 각각 빌드하고 통과했다. 최종 빌드 옵션은 모두 ON으로 복구하고 기본 실행 파일을 갱신했다.

## 자원과 응답 시간 측정

기본 ON 구성에서 32회 개폐한 기록 중 8회 준비 구간 이후의 한 측정 결과다. 측정 CSV는 빌드 폴더의 `Validation/SettingsPhase6/lifecycle-metrics.csv`에 생성되며 커밋하지 않는다.

| 측정 | 결과 |
| --- | --- |
| GDI 객체 / USER 객체 변화 | 0 / 0 |
| DXGI 로컬 GPU 메모리 변화 | 0 bytes (조회 가능한 어댑터) |
| 프로세스 PrivateUsage 변화 | +15,704,064 bytes (약 15.0 MiB) |
| 열기 + 5개 페이지 최초 그리기 평균 | 약 373 ms |
| RmlUi 렌더 프레임 평균 | 약 3.90 ms |

프로세스 메모리는 중간에 증가·감소가 있었으며 할당자/드라이버 캐시를 포함한다. 자동 검사는 준비 이후 최종 증가분 32 MiB 이내를 허용하므로, 위 결과를 ‘메모리 누수가 원천적으로 없다’는 증명으로 해석하지 않는다. GPU 수치는 DXGI의 해당 프로세스 로컬 세그먼트 사용량이며 모든 GPU 자원 유형의 직접 개수는 아니다. 이전 버전과 같은 조건의 성능 비교를 하지 않았으므로 성능 개선을 주장하지 않는다.

기본 제공 파일은 `build-rmlui-song-list/Release/BmsPlayer.exe`다. 기존 UI의 완전 제거, 접근성의 Win32 동등성 확보, 장시간 메모리 프로파일링은 별도 후속 범위다.
