# RmlUi 설정 4단계 구현

2026-10-26 / `codex/rmlui-settings-ui-test`

같은 설정 창에서 게임플레이·그래픽·사운드·기타·요약 페이지를 RmlUi로 표시한다. 이관한 설정은 HWND를 값 저장소로 사용하지 않고 기존 SettingsController의 검증·적용·INI 저장 경로를 공유한다.

| 페이지 | 이번에 연결한 항목 |
| --- | --- |
| 사운드 | 마스터·노래·키음·효과음 음량, 곡 미리보기 사용, 미리보기 음량 |
| 게임플레이 | 배속, BGA 밝기, 판정, 게이지, 노트 높이, 레인 투명도·커버, 건반별 색상, 구분선 |
| 그래픽 | FPS 목표, 노트 서브픽셀·안티앨리어싱, GPU 사용 상한 |
| 기타 | 시스템 자원 표시, 곡 선택 배경 종류·블러·불투명도, 사용자 이미지 선택 |
| 요약 | 연결을 마친 FPS·배속·밝기·판정·게이지·마스터 음량 |

GPU 사용 상한은 GPU 렌더링을 끄면 비활성화한다. 키 지정, 기어·판정선·텍스트 위치 미리보기, 화면 모드·해상도·GPU 전환·저지연·출력 버퍼, CPU/메모리 고급 항목은 기존 화면에서 제공한다. 각 페이지 아래의 기존 설정 열기 버튼으로 접근하며 네이티브 카테고리를 누르면 새 페이지로 돌아온다. 이 항목들의 전면 이관은 5단계 이후 작업이다.

## 상태와 입력

- `SettingsRmlBindings.inl`에 DOM ID와 기존 설정 명령 ID를 모았다. 선택지에는 인덱스 대신 실제 FPS·배속 단계 등 도메인 값을 사용한다.
- 모든 페이지와 요약은 같은 Snapshot을 읽는다. 변경 이벤트는 큐로 보내 RmlUi 이벤트 처리가 끝난 후 적용·저장한다. 프로그램에서 표시값을 갱신할 때 이벤트 재귀를 막는다.
- range 컨트롤의 소수점 표기 문자열도 유한한 정수 값인지 확인한 뒤 처리한다. 유효하지 않은 값은 실제 상태로 되돌린다.
- 본문만 스크롤하며 카테고리와 닫기는 고정한다. 키보드로 아래 항목에 포커스하면 본문을 해당 위치로 스크롤한다.
- 드롭다운은 RmlUi의 화면 경계 계산을 사용한다. 열린 목록에서 Esc를 누르면 목록부터 닫으며, 다시 누르면 설정 창을 닫는다.
- 사용자 이미지 선택은 이벤트 밖에서 기존 Windows 파일 대화상자를 실행한다. 선택·취소 후 Snapshot을 다시 읽고 이미지 선택 버튼으로 포커스를 복구한다. 기존 파일 복사·오류 처리·저장 방식을 유지한다.
- 초기화·문서 오류나 런타임 오류가 발생하면 실제 적용값을 유지한 채 기존 설정 화면을 제공한다.

## 검증

기존 `BmsSettingsPhase3Tests`를 4단계까지 확장했다. 합성 INI와 숨겨진 실제 Win32/RmlUi 창을 사용하여 카테고리별 표시값, 음량 키보드·마우스 드래그, 배속 키보드 선택과 요약 동기화, 드롭다운 경계, 본문 휠, 고정 탐색/닫기 영역, 취소 후 포커스, INI 재읽기, 기존 화면 전환 및 오류 복구를 확인한다. 작은 창과 192 DPI 변경 메시지도 검사한다.

물리적인 고배율 모니터 간 창 이동, 실제 파일 대화상자의 사용자 조작, 장치 전환은 자동 검증 범위 밖이다. 파일 대화상자의 취소 경로는 같은 복귀 함수를 대화상자 없는 콜백으로 검사한다. 개인 설정과 개인 곡 파일은 테스트에 사용하지 않는다.

결과: 설정 기준·컨트롤러·RmlUi 설정 통합·입력 호스트·곡 목록 렌더러/호스트·화면 테스트 7개 통과. RmlUi 전체 OFF 구성에서도 기존 설정 기준 테스트를 빌드하고 통과했다. 780×400 및 780×820 캡처를 확인했다.

최종 배포 대상은 `build-rmlui-song-list/Release/BmsPlayer.exe`이며 RML/RCSS도 같은 실행 파일 옆의 Assets/UI에 복사한다.
