# 문자·프리뷰 수정 및 FPS 진단 테스트 빌드

브랜치: `테스트` — `main`의 `21ff0ef`에서 생성. main에 병합하지 않았다.

## 문자와 프리뷰의 원인

해당 곡의 원본 BMS는 Shift-JIS/CP932이며 제목에 ASCII `@`가 아닌 **전각 `＠`(U+FF20)**를 사용한다. 원본 제목은 `ha＠ppy s＠mmer v＠c＠tion!![Normal]`, 아티스트는 `ああああ + 翡乃イスカ`이다.

이전 자동 감지는 전체 본문에서 CP949로 변환한 한글 수와 CP932의 가나 수를 비교했다. 이 곡은 WAV 파일명에 `【C】` 같은 일본식 괄호가 반복되어, CP949 오해석 결과에서 한글이 344자로 집계된 반면 실제 가나는 7자였다. 그 결과 제목의 전각 `＠`가 한글로 바뀌고 `【C】`가 들어간 키음 파일명도 함께 깨졌다. 폰트 설정 문제가 아니었다.

원본 Normal 채보의 WAV 선언 962개를 실제 폴더와 비교하면 CP949 해석은 165개를 찾지 못했고 CP932는 962개 모두 일치했다. 곡 파일이나 음원 자체는 수정하지 않았다.

`BmsText.h`에서 BOM/명시 CHARSET 우선 정책은 유지하고, 자동 감지 시 두 후보의 실제 비ASCII WAV 경로를 제한된 개수로 대조하도록 수정했다. 파일 근거가 동률이면 제목·아티스트·장르 등의 메타데이터를 우선 평가한다. 반복되는 WAV 선언 수가 언어 판단을 왜곡하지 않게 했다. ASCII 제목과 한국어 음원 파일명을 가진 CP949 채보도 회귀 테스트에 포함했다.

프리뷰는 별도 음원이 없는 곡의 키음을 합성하는 기존 경로를 사용한다. 원본 곡으로 실제 SongPreview worker와 오디오 시작 경로를 실행해 **샘플 962개 연결, 누락/무정의 0, 프리뷰에 필요한 780개 샘플 모두 디코딩**을 확인했다. 자동 검증의 출력은 무음으로 했다. 모든 구간의 청감 비교까지 수행한 것은 아니다.

합성 프리뷰에 롱노트의 별도 끝점 키음도 포함하도록 보완했다.

## 화면 하단 FPS의 의미

테스트 실행파일에서 아래처럼 표시한다.

```text
FPS NOW 1000  AVG 980  1% LOW 812  OUTPUT 240
```

- **NOW:** 최근 약 0.25초 동안의 렌더 프레임 수 / 실제 경과 시간. 순간값의 과도한 깜빡임을 줄였다.
- **AVG:** 곡 시작/재시작 이후 활성 플레이의 전체 프레임 수 / 실제 경과 시간. 로딩과 일시정지 시간은 제외한다.
- **1% LOW:** 최근 10초에서 가장 느린 1%의 프레임 시간 평균을 FPS로 환산한다. 최솟값 한 개나 단순 FPS 평균이 아니다. 샘플 수는 올림하며 한 프레임 이상 사용한다. 1초마다 재계산한다.
- **OUTPUT:** GPU 경로의 기존 제출률 표시. 렌더 루프 FPS와 별도이며 물리 모니터가 표시한 고유 프레임 수와 동일하다고 보장하지 않는다.

프레임 기록은 고정 버퍼에 저장해 매 프레임 할당하지 않는다. 표시 문자열도 0.25초 단위로 캐시해 매 프레임 문자열 조립을 피한다. 최대 32,768개를 유지하며 1500FPS 상한의 최근 10초를 수용한다. 1% LOW는 매 프레임 전체 정렬하는 대신 1초에 한 번 고정 scratch 버퍼와 nth_element로 계산한다.

## 비프 테스트 동작

연속 플레이 3초 후부터 **NOW가 AVG보다 100FPS 이상 낮아지면**, 880Hz·약 45ms의 짧은 비프를 낸다. 기존 WASAPI 효과음 믹서에 큐를 넣으며 렌더 스레드에서 `Beep`나 sleep을 호출하지 않는다.

계속 낮은 상태에서는 반복해서 울리지 않는다. NOW가 AVG−50 이상으로 회복하면 재감지하며, 알림 사이에는 최소 2초 간격을 둔다. 일시정지에서 복귀한 직후 3초도 감지를 유예한다. 음량은 기존 마스터/효과음 설정을 따른다. 음소거 상태에서는 들리지 않는다.

## 빌드·실행

별도 CMake target은 `BmsPlayerTest`, 실행파일 이름은 `BmsPlayer-Test.exe`이다. 프레임 통계·알림은 `BMS_FRAME_DIAGNOSTICS`를 지정한 이 target에서만 활성화된다.

```powershell
cmake --build build-performance-hybrid --config Release --target BmsPlayerTest
```

편의를 위해 검증한 테스트 실행파일을 `build/Release/BmsPlayer-Test.exe`에도 복사했다. 기존 `BmsPlayer.exe`는 교체하지 않는다. 같은 디렉터리의 Songs/Assets를 사용하므로 전체 라이브러리를 다시 복사할 필요가 없다.

테스트 설정은 실행파일 옆 `BmsPlayer-Test.ini`, 기록은 `BmsPlayer-Test-records.ini`를 사용한다. 첫 테스트 실행용 설정은 기존 설정의 복사본으로 준비하며 이후 원본 설정과 독립적으로 저장한다. 창 제목에 `TEST / FPS Diagnostics`를 표시한다. `BMS_PLAYER_CONFIG_PATH`를 명시하면 해당 경로가 우선한다.

## 검증

- FrameStatistics 단위 검사: 안정 FPS, 평균, 느린 1% 계산, 하락 알림·회복·쿨다운, 일시정지 제외, 최근 구간 만료.
- Parser 회귀 검사: WAV 이름 반복이 많은 CP932, 원본 전각 `＠`와 일본어 아티스트 보존, CP949 한국어 파일명, 기존 명시 인코딩/BOM.
- Diagnostics 통합 검사: 비프 PCM이 실제 믹서에 도달하고 50ms 이내 끝나는지, 테스트 HUD 렌더 캡처, 실제 곡 프리뷰의 모든 필요 키음 디코딩.
- 기존 오디오·화면·호환성·라이브러리 검사도 함께 실행했다. 관련 회귀 검사 **8/8 통과**. 표시 문자열 캐시 보강 후 통계/HUD 검사 2개도 다시 통과했다. 상세 결과는 빌드 폴더의 CTest 로그를 참고한다.

진단 HUD 캡처: `build-performance-hybrid/Validation/Diagnostics/fps-hud.bmp`. 실제 곡은 자동 테스트의 필수 입력이나 Git 커밋에 포함하지 않았다.

이 기능은 프레임 하락을 관찰하기 위한 도구다. 비프 자체로 프레임 하락의 원인까지 식별하는 것은 아니며, 아직 캡처하지 않은 모든 드랍 구간을 수정했다고 주장하지 않는다.
