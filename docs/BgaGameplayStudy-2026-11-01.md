# SevenMania BGA 최적화 실측 보고서

2026년 11월 1일 · Windows Release · 실제 플레이 경로

**FREEDOM DiVE에서는 반복되는 BMP 전환의 CPU 합성을, ENERGY SYNERGY MATRIX에서는 새 영상 프레임의 전체 화면 CPU 복사를 줄였다.** 두 곡 모두 해당 경로가 실제로 실행됐다. 변경된 줄만 GPU에 업로드하는 경로와 투명 레이어 분리를 함께 채택했다. 백그라운드 합성은 영상 시점이 뒤처지는 결과가 있어 진단 실험으로 끝냈다.

최종 빌드에서 가장 느린 0.25초 창은 FREEDOM DiVE 두 회 모두 0.839–0.845ms, ENERGY 두 회 모두 약 0.872ms였다. 다만 드문 단일 프레임은 악화됐다. FREEDOM DiVE의 P99.9는 3.399–3.434ms에서 3.738–3.787ms로, ENERGY는 3.615–3.711ms에서 3.905–4.040ms로 늘었다. 이 실험으로 BGA 재합성 비용 감소는 확인했지만 잔여 끊김의 원인은 특정하지 못했다.

## 측정 조건과 지표

- 주 대상은 FREEDOM DiVE [ANOTHER 7]의 `dive_a7.bme` 2,222노트이며, 설치 폴더에는 BMP 109개와 WAV 383개가 있다. ENERGY SYNERGY MATRIX의 `_another.bms`는 2,080노트다. 해당 추가 차분 폴더에는 WMV 1개가 있고 별도 키음·음악 파일은 없다.
- 실제 엔진에서 각 빌드·채보당 2회씩 같은 입력 일정을 재생했다. 두 실곡은 30초부터 9초간 재생하고 시작 후 1초부터 8초 직전까지 분석했다. 복합 레이어 시험은 무음 노트, 영상과 검은색 투명 키를 가진 두 BMP를 사용했다. 3초부터 7초간 재생하고 중앙 5초를 집계했다.
- 실제 창은 1920×1061, GPU 하이브리드 출력, FPS 무제한, DirectComposition 및 Reflex를 요청했다. 격리 설정에서 성능 표시를 켰다. GPU 폴백·Reflex 활성 여부는 각 로그로 확인할 수 있다.
- 아래 단위는 ms이며 두 실행 각각의 통계를 계산한 뒤 범위로 표시했다. P99와 P99.9는 갱신 시작 간격의 99·99.9백분위다. ‘최저속 0.25초 구간’은 고정 0.25초 창 중 평균 간격이 가장 긴 창이다. 게임의 FPS NOW와 유사하지만 집계 시작 시각은 다르다. ‘재합성 CPU’는 배경이 무효화된 프레임만의 `backplate_build_ms` 평균으로 GPU 실행·최종 화면 표시·전체 BGA 처리 비용은 포함하지 않는다.
- 게임 시계·노트 입력·프레임 표시가 비동기이므로 실행 순서, 스케줄링, 제출 시각에 변동이 있다. 표본은 한 PC의 짧은 구간이다.

## 복합 레이어 및 백그라운드 합성

| 빌드 | 평균 | P99 | P99.9 | 최저속 0.25초 구간 | 재합성 CPU |
|---|---:|---:|---:|---:|---:|
| 투명 레이어 CPU 합성 | 0.883–0.884 | 3.620–3.657 | 3.955–4.155 | 0.901–0.907 | 2.758–2.760 |
| 부분 업로드 추가 | 0.900–0.914 | 3.628–3.633 | 4.116–4.577 | 1.202–1.530 | 2.754–2.769 |
| GPU 레이어 분리 | 0.914–0.920 | 1.656–1.677 | 3.496–3.802 | 0.948–0.949 | 0.001–0.001 |
| 백그라운드 CPU 합성 실험 | 0.823–0.831 | 1.290–1.596 | 3.982–4.108 | 0.841–0.847 | 0.102–0.102 |
| 최종 GPU 분리 + HUD 영역 재사용 | 0.834–0.834 | 1.620–1.661 | 3.179–3.432 | 0.859–0.861 | 0.001–0.001 |

1. **단일 영상 직접 전달**은 화면 전체를 불투명하게 덮는 같은 크기의 영상에만 적용한다. 나머지 효과·크기에는 기존 합성 경로를 유지한다.
2. **레이어 분리**는 화면 전체를 덮는 불투명 이미지면 하위 레이어의 합성을 생략한다. 지원되는 투명 정지 이미지와 전체 화면 영상 조합에서는 두 GPU 비트맵을 분리하고, CPU HUD에 필요한 영역만 배경 또는 배치가 변할 때 다시 합성한다. 키 색상, 투명도, 크기 등 조건이 다르면 일반 경로를 사용한다.
3. **부분 업로드**는 마지막으로 실제 업로드에 성공한 불변 배경과 비교한다. 위·아래의 동일한 줄을 제외한 범위만 전송한다. 가로로 작은 변경도 해당 줄 전체를 보내며, 임의의 CPU 레이어 조합에 대한 부분 재합성까지 구현한 것은 아니다.
4. **백그라운드 합성 실험**은 복합 영상과 이미지가 함께 보이는 경로에 한정했다. 대기 작업을 하나로 제한하고 완성된 결과만 사용했다. 두 복합 실행에서 결과를 선택한 428회 중 207회, 430회 중 208회가 당시 디코더의 최신 프레임보다 이전 영상을 참조했다. 미디어 타임스탬프 차이는 최대 100ms였다. 이 값은 모니터 지연 측정값이 아니다. 실곡의 단일 레이어에서는 작업자 경로가 활성화되지 않아 이 방법의 평가는 복합 시험에 근거한다.

## 검증과 해석

- CPU 기준 이미지와 직접 전달 이미지의 픽셀 비교, 투명 이미지의 잘못된 가림 방지, 캔버스 크기가 바뀐 후 캐시 픽셀 수명, 한 줄만 바뀐 GPU 업데이트의 전 화면 RGB 비교, 투명 GPU 레이어와 CPU 혼합 기대값 비교를 수행했다.
- 원래 시험의 `control`은 폴더 내 영상을 자동으로 찾아 실제로 배경이 갱신됐다. BGA가 없는 대조군에서 제외했다.
- CPU 재합성 단축은 확인했다. 두 번의 측정 범위가 겹치는 프레임 지표에는 확정적인 개선율을 부여하지 않았다. 사용자 환경의 1200→600 FPS 현상이나 실제 모니터의 끊김이 사라졌다고 판단할 근거는 부족하다.
- 원시 CSV·실행 로그·시험 입력 및 집계 스크립트는 프로젝트의 `build-rmlui-song-list/Validation/BgaPlayStudy/`에 있다. 개인 곡 파일과 빌드 산출물은 Git에 포함하지 않았다.
- 재현은 같은 격리 설정을 지정하고 `BmsGameplayProfile.exe <채보> <출력.csv> gpu 30 9 0 reflex`로 실행한다. FREEDOM DiVE 채보 SHA-256은 `2524641a93e2a2d5cd8a0db134ddf5ddd522b73b8d60cfb819daef02de9c85b7`, ENERGY는 `75eb8ee47975d97db7de7ba7977c6caa855fc168bbcecb95fb7909d7377dced4`다.
