# 폴더 선곡 및 캐시 2차 개선

## 구현과 수정 원인

1. `variant selection should wrap forward`: 작업 시작 시 로컬 작업 트리의 C++/Rust 구현이 마지막 인덱스를 clamp하고 있었다. 커밋 HEAD에는 순환 코드가 있었으므로 폴더 ID 도입 자체가 원인이 아니라 기존 로컬 순환 변경과 테스트 의도가 충돌한 것이다. 폴더 ID는 음수, 그룹은 0 이상이므로 ID 충돌 원인이 아니다. 두 구현 모두 나머지 연산을 이용한 순환으로 복구했다. 기존 정방향/역방향 순환 검증은 제거하지 않았다.
2. 캐시 선표시: 기존 로딩 worker는 import 후 원본 BMS를 검사하지 않는 캐시 snapshot을 읽고 정상 로딩 완료 메시지로 게시한다. 캐시가 없거나 버전이 다르면 기존 전체 분석을 수행한다. 시작 시 `scanFolder(Songs)`가 빈 sources가 아니라 `{Songs}`를 전달한다는 점까지 반영했다. 다른 폴더에서 곡을 가져오는 import는 완료 후 검증된 전체 검색을 사용한다.
3. 증분 검증: `SongIndexWorker`가 자기 자료구조만 수정한다. mutex로 완성된 결과를 넘기고 PostMessage로 UI에 알린다. UI만 gCharts/곡 묶음/기록 키/목록을 교체한다. 설정/연습 창이 열려 있으면 결과를 mailbox에 유지하고 선곡 tick에서 닫힌 뒤 반영한다. 실제 채보 경로로 선택된 곡과 난이도를 복원하고 없어진 항목은 기억한 행을 유효 범위로 제한한다. 최초 스캔 뒤에도 같은 검증 경로로 빈 폴더 정보를 보충한다.
4. 플레이/재검색/종료는 검증 worker를 취소하고 join한다. 플레이에서 선곡 화면으로 돌아오면 검증을 다시 시작한다. 이미 큐에 있던 신호는 비어 있는 mailbox로 안전하게 무시된다. 미검증 캐시 항목도 플레이 시 기존 전체 파일 재분석/오디오 준비 경로를 거치며, 삭제/손상 파일은 기존 로딩 실패 처리로 돌아간다.
5. 곡 묶음: 실제 디렉터리 + 정규화한 제목 + 오디오 리소스 경로 집합의 fingerprint를 사용한다. 아티스트 표기 차이나 키 모드만으로 강제 분리하지 않는다. 리소스 근거가 없으면 개별 채보로 분리한다. 같은 폴더의 다른 제목 또는 같은 제목의 다른 리소스는 별도 곡이 된다. Rust ABI의 directory 문자열은 내부 그룹 식별자로 전달하며 폴더 탐색은 항상 실제 Chart.path로 한다. C++도 같은 규칙을 사용한다. 플레이 기록 키와 파일 형식은 변경하지 않았다.
6. 캐시 버전을 올려 리소스 fingerprint를 저장한다. 삭제된 채보의 .meta를 성공한 검증 뒤 정리한다. 손상/부분 파일/다른 버전은 parser로 복구하며 쓰기 실패는 검색을 막지 않는다. F5 재검색은 캐시를 무효화하고 다시 분석한다. 원자적 교체와 문자열/수치 범위 검증은 유지했다.
7. 빈 폴더는 background 파일 탐색 결과로 제공한다. 폴더와 실제 선택 채보 경로를 UTF-16 이진 상태 파일에 저장/복원한다. 모르는 경로는 받아들이지 않고, 검증 후 삭제된 폴더는 루트로 돌아간다. ALL SONGS에서도 원본 채보 인덱스로 기록을 조회한다.
8. BGA 미리보기: BrowseBackdrop의 BGA 모드에서 catalogOnly인 선택 항목만 SelectedBgaMetadata가 비동기로 분석한다. 원본 BGA snapshot을 재사용하며 노트/음원 샘플을 결과에 남기지 않는다. 요청·결과는 각각 하나로 제한하고 지나간 선택의 결과는 버린다. 전체 라이브러리의 BGA 이미지/동영상은 시작 시 디코딩하지 않는다.

## 검증

- Release BmsPlayer와 관련 테스트 빌드 성공. 기본 배포 이름 `build-rmlui-song-list/Release/BmsPlayer.exe`를 사용했다.
- CTest: BmsLibraryTests, BmsSongSelectionTests, SevenManiaSkinBindingTests, BmsLowLatencyTests, BmsFrameTests 통과.
- Rust를 끈 별도 검증 빌드의 C++ SongSelectionTests도 통과했다. 기본 배포는 Rust ON을 유지한다.
- Rust crate 자체 unit test 1개 및 doc test 실행 성공. 기본 PATH에 cargo가 없어 프로젝트 로컬 cargo/RUSTUP_HOME을 사용했다.
- 라이브러리 테스트: 캐시 없는 스캔/캐시 snapshot, 원본 삭제 전후 캐시 선표시와 검증 제거, 변경 재분석, 손상 복구, 삭제 캐시 정리, 빈 유니코드 폴더, worker 완료/취소, 폴더/선택 경로의 디스크 재로딩, ALL/상위 이동, 기존 import/취소/긴 경로.
- 선곡 테스트: 순환, 같은 디렉터리의 독립 곡, 동일 제목·다른 오디오, 기존 차분 묶음, 총 채보 수 보존. 기존 차분 fixture에는 같은 오디오를 명시해 묶음 근거를 제공했다.
- BGA worker 테스트는 원본 parser 결과와 이벤트 수·ID·레이어·시간·이미지 경로를 비교한다. 파서가 자동 복구 이벤트를 추가할 수 있어 임의로 1개라고 가정하지 않는다. 이 테스트는 실제 화면의 영상 픽셀 동등성 검증은 아니다.
- 기존 기록 저장/재로딩 및 스킨 바인딩·렌더링 회귀도 통과했다. 사용자 스킨에 새 필수 필드를 추가하지 않았다.

## 측정

실제 `Release/Songs`의 788개 채보에서 진단 도구로 측정했다. 캐시를 무효화한 인덱싱과 캐시 읽기/증분 검증을 같은 프로세스에서 순서대로 실행했다. OS 디스크 캐시를 비운 시험은 아니다.

| 항목 | 측정 |
|---|---:|
| 캐시 없는 인덱싱 | 4416.28ms |
| 캐시 snapshot 읽기 | 47.4464ms |
| 변경 없는 증분 검증 | 99.4884ms |
| 폴더 왕복 평균(100회) | 1.97396ms |
| 진단 프로세스 private memory | 66.2344MiB |
| 진단 프로세스 peak working set | 92.8516MiB |

snapshot 시간은 UI 첫 표시 시간이 아니다. 폴더 왕복은 메모리 탐색 모델의 시간이며 RmlUi 렌더링·입력 시간을 제외한다. 메모리도 배포 플레이어 전체가 아닌 진단 도구의 값이다. 스캔 CPU 사용률·실제 선곡 프레임 타임은 측정하지 않았다. 원시 로그는 커밋하지 않은 Validation/folders-performance.txt에 있다.

재현: `Release/BmsLibraryTests.exe --index-profile Release/Songs` (빌드 폴더 기준). 실제 사용 중인 파일 경로를 넘긴다. 이 명령은 해당 폴더의 메타데이터 캐시만 지우고 재구축하며 곡/기록 파일은 수정하지 않는다.

## 남은 한계

- 캐시 선표시·목록 교체·플레이 진입을 실제 창에서 자동 조작하는 E2E 테스트, 실제 앱 종료/재시작 UI 복원, 대규모 스캔 중 프레임 타임은 미검증이다. worker와 navigation 단위 검증을 전체 UI 검증으로 보고하지 않는다.
- 이미 시작한 한 파일의 parser 호출 내부는 취소하지 못한다. 취소/join은 그 호출이 끝날 때까지 기다릴 수 있다. 선택 BGA worker도 reset 이후 진행 중이던 분석을 버리지만 내부 I/O를 강제 중단하지 않는다.
- 빈 폴더와 비어 있던 마지막 폴더의 복원은 background 검증 결과 도착 이후에 보충된다. 캐시 선표시 시점에 모든 빈 폴더가 미리 복원되는 것은 아니다.
- 곡명과 리소스 집합이 조금이라도 달라 모호한 차분은 별도 곡이 될 수 있다. fingerprint는 비보안 용도의 64비트 해시이며 모든 곡의 의미적 동일성을 판정하는 알고리즘은 아니다.
- 크기/mtime를 유지한 변경과 기존 미디어 내용만 교체한 변경은 자동 탐지하지 못할 수 있다. F5 강제 재검색을 제공한다. 남은 .tmp는 snapshot에서 무시되며 다른 실행 중인 프로세스의 파일을 삭제하지 않도록 자동 일괄 삭제하지 않는다.
- 검증 worker의 오류는 현재 목록을 유지하는 정책이다. 오류의 상세 UI 안내와 재시도 정책은 추가 개선 대상이다.

다음 우선순위는 실제 UI E2E/프레임 측정, 취소 지연 계측, 빈 폴더 인덱스의 선복원이다. 관련 없는 사용자 변경은 커밋하지 않았다.
