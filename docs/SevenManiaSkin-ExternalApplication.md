# 외부 스킨 불러오기와 화면 적용

작성일: 2026-10-28

## 사용 방법

1. 설정 → 게임플레이 → **외부 스킨**으로 이동한다.
2. **스킨 불러오기...**에서 `.semaskin` 파일을 고른다.
3. 검증과 이미지·폰트 준비를 통과하면 즉시 적용한다. 현재 스킨 이름·지원 화면·선택 파일 경로를 표시한다.
4. **기본 화면으로 복원**하면 적용과 저장된 선택을 해제한다.

기존 Win32 설정창으로 전환해도 게임플레이 페이지 아래에 같은 불러오기/복원 버튼이 있다. RmlUi가 꺼진 빌드에서도 사용할 수 있다.

스킨은 선택한 외부 파일을 직접 읽는다. 별도 Skins 폴더에 설치/복사하지 않으며, 한 번에 한 패키지를 선택한다. 다음 실행에도 사용하려면 외부 파일을 이동하거나 삭제하지 않아야 한다. 파일 변경을 자동 감시하지는 않는다. 수정한 스킨은 다시 선택해 불러오면 된다.

선택 취소 또는 검증 실패는 기존 적용과 저장 경로를 바꾸지 않는다. 시작할 때 저장된 파일이 없거나 손상되었으면 기본 화면으로 시작하고, 설정에서 오류를 확인할 수 있다. 복원 버튼은 저장 경로 오류 상태에서도 사용할 수 있다.

## 현재 적용되는 범위

manifest의 supportedScreens에 선언한 곡 선택·플레이·리절트에 이미지/텍스트/숫자 레이어를 적용한다. 부분 스킨이 지원하지 않는 화면은 그대로 기본 화면을 사용한다. 데이터는 3차의 읽기 전용 캡처/스냅샷을 이용한다.

기존 화면에 레이어를 덧그리는 초기 적용 방식이다. 곡 목록과 메뉴의 입력·버튼, 노트 배치·판정·점수·게이지 계산을 스킨으로 교체하지 않는다. GPU 플레이에서는 스킨을 기존 노트/HUD/일시정지 전경보다 먼저 출력한다. CPU 플레이에서는 스킨을 일시정지 메뉴보다 먼저 출력한다. 일반 Win32 자식 컨트롤은 스킨 위에 남는다. 스킨 전체 디자인·숫자 이미지 폰트·키프레임/이벤트 효과·LR2 변환은 추가하지 않았다.

검증용 패키지 예시는 `tests/fixtures/skins/data-binding.semaskin`이다. 완성된 디자인이 아닌 바인딩 테스트용이며, 일부러 존재하지 않는 키/잘못된 화면 키도 포함한다.

## 구현

| 파일 | 내용 |
| --- | --- |
| `src/skin/SkinApplication.h/.cpp` (추가) | 외부 패키지의 원자적 교체, 선언 화면 사전 준비, CPU 합성 캐시, 직접 GPU 출력, 해제/복구 |
| `src/SkinApplicationHost.inl` (추가) | 파일 선택기, 설정 저장/복원, 설정 액션과 실제 게임 데이터 연결 |
| `src/Main.cpp` | 게임플레이 설정 버튼, 시작/종료 수명, 곡 선택·리절트·플레이 렌더 훅 |
| `src/SettingsRmlPage.inl` | 버튼 이벤트를 UI 메시지로 예약, 현재 선택 상태 동기화 |
| `Assets/UI/settings.rml/.rcss` | 게임플레이 탭의 외부 스킨 카드와 긴 경로 줄바꿈 |
| `src/CompositionPresenter.h` | 준비된 외부 레이어용 일반 함수 포인터 훅. 기존 노트/HUD 앞에서 호출하며 reset 시 해제 |
| `src/skin/SkinRenderer.h/.cpp` | 빈 문자열로의 전환까지 감지하는 textChanges 카운터 추가 |
| `CMakeLists.txt`, `cmake/SkinSystem.cmake` | 모듈·Windows 링크·자동화 테스트 등록 |
| `tests/SkinApplicationTests.cpp` (추가) | 실제 설정/게임 호스트를 포함한 통합 검사 |

기존 BMS 파서·판정·오디오·입력·곡 선택 로직은 바꾸지 않았다. 별도 외부 라이브러리는 추가하지 않았다. 작업 전에 존재하던 다른 변경은 커밋에 포함하지 않는다.

패키지를 바꾸기 전에 로더 검사와 선언 화면의 이미지/글리프 준비를 모두 완료한다. 후보 준비가 실패하면 이전 선택을 유지한다. COM/GDI 객체와 텍스처는 소유 객체의 수명으로 해제한다. 같은 ID를 가진 수정본도 새 파일 선택으로 교체할 수 있다.

게임플레이 GPU 경로는 CompositionPresenter의 실제 Direct2D target을 사용한다. target이 바뀌었을 때 한 번 준비하고, 각 프레임에서는 데이터 갱신과 준비된 비트맵 출력만 수행한다. 이 경로는 CPU 합성용 staging readback을 사용하지 않는다. 기존 프레젠터의 큐/저지연/Present 처리는 유지한다.

곡 선택·리절트·CPU 플레이 경로는 투명 DirectX 오프스크린 표면을 캐시하고 AlphaBlend로 합성한다. 화면 종류/크기 또는 최종 표시 문자열이 바뀔 때만 GPU 표면을 읽어온다. 바인딩에 쓰이지 않는 값의 변경은 캐시를 다시 만들지 않는다. 화면 해상도가 바뀌면 해당 도메인의 텍스처를 재준비하므로 큰 스킨에서는 전환 비용이 생길 수 있다. CPU 합성 표면은 최대 한 변 8192, 총 16,777,216픽셀이다. 넘으면 기본 화면을 유지한다.

잘못된 크기나 장치/그리기 실패는 오류 상태로 전환하며 같은 실패를 매 프레임 재시도하지 않는다. 정상 크기로 돌아오거나 새 GPU target을 준비하면 복구를 시도한다. 게임 데이터는 UI 스레드에서만 읽는다. 스킨 파일을 프레임마다 다시 읽거나 압축 해제하지 않는다.

## 설정 저장

기존 설정 INI의 `[Skin] PackagePath`에 선택을 저장한다. 원래 INI가 ANSI일 수도 있으므로 UTF-8 경로를 ASCII hex 문자열(`utf8:` 접두부)로 저장해 한글·일본어·이모지 경로의 코드 페이지 손실을 방지한다. 화면에는 디코딩한 원래 경로만 표시한다. 기존/수동으로 기록한 절대 경로도 읽는다. 형식이 잘못되었거나 잘린 값은 기본 화면으로 처리한다.

저장에 실패하면 현재 적용은 유지하되 상태에 저장 실패를 표시한다. 이 경우 다음 실행까지 선택이 보존된다고 보장하지 않는다. 내부 저장 제한을 넘는 극단적으로 긴 경로도 같은 방식으로 처리한다. 다른 게임 설정이나 키 배치를 덮어쓰지 않는다.

## 검증

```powershell
cmake --build build-rmlui-song-list --config Release --target BmsPlayer SevenManiaSkinApplicationTests
ctest --test-dir build-rmlui-song-list -C Release --output-on-failure -R '^SevenManiaSkin'
```

- RmlUi의 실제 버튼 이벤트 → 예약된 설정 액션 → 파일 적용·해제·포커스 복귀를 검사했다. 파일 선택기의 반환만 테스트 함수로 주입하며, Windows 파일 선택창 자체를 자동 조작한 검사는 아니다.
- Win32 버튼을 통한 동일 동작, 취소, 잘못된 ZIP, 부분 스킨, 한글/이모지 경로와 실제 INI 저장, 저장 값 복원, 시작 시 파일 누락, 기본 화면 복원을 검사했다.
- 실제 곡 선택/CPU 플레이/리절트 출력, 변경 없는 화면의 readback 재사용, 제목 변경 및 빈 표시 갱신, 해상도 변경·과도한 크기 차단·복구를 검사했다.
- 실제 CompositionPresenter에서 스킨과 게임 점수를 출력하고, 기본 전경이 위에 남는 것·장치 재생성·일시정지 경로·플레이 중 CPU 합성 readback 미사용을 검사했다.
- 패키지 반복 적용/해제 5회와 GDI 핸들 정리를 검사했다. 이는 전체 GPU 메모리 누수나 장시간 프레임 안정성을 완전히 증명하는 검사는 아니다.
- 설정 PNG를 열어 카드·버튼·긴 경로의 배치를 확인했다. 결과는 `build-rmlui-song-list/Validation/SkinApplication/settings-skin.png`와 `applied-gpu.png`에 저장한다.

최종 Release 기본 BmsPlayer.exe 빌드에 성공했다. 추가한 SevenManiaSkinApplicationTests는 RmlUi ON에서 90회, OFF의 Win32 전용 경로에서 67회 assertion을 통과했다. 로더 97개, 이미지 612회, 바인딩 353회 검사도 통과했다. RmlUi 전체 OFF 빌드에서도 스킨 관련 4개 테스트가 모두 통과했다.

기존 기능을 포함한 11종 검사에서는 GPU·표시·핵심·Rml 곡 목록·목록 호스트·설정 Phase5·스킨 4종의 10종이 통과했고 BmsSongSelectionTests 1종이 실패했다. 기존 BmsSongSelectionTests의 `variant selection should wrap forward` 실패는 별도 미커밋 C++/Rust 전환 동작과 테스트 기대값 차이이며 이번 작업에서 변경하지 않았다. 모든 화면의 장시간 수동 플레이·실제 파일 선택창 조작·실제 GPU 제거는 검사하지 않았다.
