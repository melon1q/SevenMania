# 5K / 7K / 10K / 14K / PMS 9K 지원 현황 — 2026-11-09

커밋 7d81fa6에서 전 키 모드 플레이를 허용한 뒤 7K 중심으로 남아 있던 입력·표시·테스트를 보강한 기록이다. 이 문서는 그 시점(커밋 f0709b5~2922a73 및 이 문서의 커밋)의 상태를 설명하며, 이후 코드와 다를 수 있다. 수동 하드웨어 플레이(실제 컨트롤러, 키보드 연타)는 검증하지 않았다.

## 모드별 현황

| 모드 | 레인 번호 | 키보드 | 컨트롤러 | 표시(스킨 없을 때) | 스킨 기어(기본 스킨) |
|---|---|---|---|---|---|
| 5K | 0 = 스크래치, 1-5 | 지원 | 지원 (1P 슬롯) | 기본 덱(레인 색 버튼) | 지원 (7K 건반 텍스처) |
| 7K | 0, 1-7 | 지원 | 지원 | 스킨 덱 | 지원 |
| 10K | 1P 0-5, 2P 8-13 (6, 7, 14, 15는 비어 있음) | 지원 | 지원 (2P 버튼 지정 필요) | 기본 덱, 2P 스크래치 우측 | 지원 |
| 14K | 1P 0-7, 2P 8-15 | 지원 | 지원 (2P 버튼 지정 필요) | 기본 덱, 2P 스크래치 우측 | 지원 |
| PMS 9K | 0-8 (스크래치 없음) | 지원 | 지원 (2P 건반 1-2 지정 필요) | 기본 덱, 대칭 색 | 지원 |

- 레인 번호는 파서·판정이 쓰는 논리 번호다. 화면 위치는 `LaneLayout::position()`이 따로 정하며, DP는 `SC 1-7 | 1-7 SC` 순서로 2P 스크래치(레인 8)를 오른쪽 끝에 그린다 (`src/LaneLayout.h`).
- `ChartMode`의 숫자값(0-6)은 메타데이터 캐시와 Rust FFI에 저장되므로 바꾸지 않는다. 새 모드는 `Other` 뒤에 추가한다 (`src/BmsParser.h`, 테스트에서 `static_assert`).

## 기본 키 배치

설정 파일(`%APPDATA%\BmsPlayer\keybindings.ini`)에 저장된 모드는 그대로 두고, 저장값이 없는 모드만 아래 기본값을 쓴다.

| 모드 | 1P | 2P |
|---|---|---|
| 5K | LShift, S D F Space J | - |
| 7K | LShift, S D F Space J K L | - |
| 10K | LShift, Z S X D C | RShift, M K , L . |
| 14K | LShift, Z S X D C F V | RShift, M K , L . ; / |
| PMS | Z S X D C F V G B | - |

- 예약키(Esc, Enter 등)나 중복 키가 설정 파일에 있으면 그 레인만 기본값으로 되돌린다. 되돌린 기본값이 다른 키와 겹치면 해당 모드만 전체 기본값으로 되돌린다. 되돌릴 때마다 `KeyProfiles::warnings`에 기록하고 디버그 출력에 남긴다. 설정 화면에 표시하지는 않는다.
- 키 설정(캡처)과 설정 화면의 키 목록은 화면의 왼쪽→오른쪽 순서를 따른다. DP는 `1P SC, 1-7, 2P 1-7, 2P SC` 순이며 프롬프트에 "2P 3번 건반"처럼 대상이 표시된다. 저장 형식(`LaneN`)은 레인 번호 순서 그대로다. 이 순서가 바뀌기 전(레인 순서로 2P 스크래치를 먼저 묻던 때)에 DP 키를 설정했다면 2P 키가 한 칸씩 밀려 저장되어 있을 수 있으니 다시 설정하거나 "기본 키 배치로 복원"을 쓴다.
- 레인→키 변환은 `src/KeyLaneMap.h`(`laneKeyFor`, `keyProfileSlot`)에 있고 `Main.cpp`의 `laneKey`가 이를 호출한다.

## 컨트롤러

- 입력은 16슬롯(DP 번호: 0 = 1P 스크래치, 1-7 = 1P 건반, 8 = 2P 스크래치, 9-15 = 2P 건반)으로 만든 뒤 `controllerSlotLane`이 모드별 레인으로 바꾼다.
- 5K/7K/10K/14K는 슬롯 번호가 레인 번호와 같고 쓰지 않는 슬롯은 무시한다. PMS는 스크래치가 없어 1P 건반 1-7이 레인 0-6, 2P 건반 1-2가 레인 7-8이다. 따라서 PMS 9버튼을 모두 쓰려면 2P 건반 1-2도 지정해야 한다.
- 2P 버튼은 컨트롤러 설정 창의 오른쪽 열에서 지정하며 `Key2P1~7`, `Scratch2PCW`, `Scratch2PCCW`로 저장한다. 지정하지 않으면(기본) 기존 1P 동작과 같다. 턴테이블 축은 1P 스크래치에만 연결된다.

## 표시

- 구분선: 설정의 구분선 7개 값을 `LaneLayout::separatorIndex()`로 레인에 연결한다. DP는 1P 스크래치 옆, 플레이어 경계, 2P 스크래치 옆에 그려진다. 폭이 0인 레인(5K의 6-7번, 10K의 빈 레인) 가장자리에는 그리지 않는다.
- 색: `LaneLayout::colorSlot()`이 기존 레인 색 8개 중 하나를 고른다. PMS는 양끝이 같은 색이고 스크래치 색은 중앙 버튼에만 쓴다.
- 비7K 덱은 레인 색을 따르는 단순 버튼이며, 눌리면 밝아진다.

## 스킨 기어와 에디터

- 기본 스킨(`DefaultReference.semaskin`)에 5K/10K/14K/PMS 기어를 추가했다. 모든 모드가 7K의 `white-key`/`black-key` 건반 이미지와 스크래치 이미지를 쓴다. 형식과 요소 ID는 [LiveSkinGear.md](LiveSkinGear.md)의 "키 모드별 기어"에 있다.
- 스킨 에디터 play 화면에 `기어 7K / 5K / 10K / 14K / PMS` 버튼이 있어 모드별로 기어 요소의 위치·크기·표시 여부를 편집할 수 있다. 저장 시 7K 배치가 기본값으로, 나머지는 요소의 `extensions.gearModes`에 기록된다.
- 14K처럼 기어가 넓은 모드는 왼쪽 위치 기준 좌표가 음수(예: 패널 x=-17)가 되어 에디터 캔버스 왼쪽 가장자리를 벗어난다. 레이어 목록에서는 선택·편집할 수 있다.
- 스킨 기어의 키 가이드(버튼 위 글자)는 모든 모드에서 게임이 지정 키 이름으로 채운다. 이전에는 7K 글자(S D F …)가 스킨에 고정되어 있었다.
- 에디터의 새 버튼은 화면에서 직접 눌러 확인하지 못했다. 에디터 로직(모드 전환, 저장 시 7K 기본값 보존)과 렌더링은 `SevenManiaGearModeTests`로 확인했다.

## 테스트

`SevenManiaGearModeTests`(`tests/GearModeTests.cpp`)는 기본 스킨의 모드별 기어 렌더링(패널 폭, 레인별 눌림, 7K 불변)과 에디터의 모드 전환·저장을 확인한다. `BmsKeyModeLaneTests`(`tests/KeyModeLaneTests.cpp`)가 다음을 확인한다: 모드별 채널→레인 매핑(노트, 롱노트, 인비저블, 지뢰), `chartLanes`/레이아웃 일관성, MIRROR/RANDOM/`notes_copy`, 키 프로필 기본값과 로드 폴백, 컨트롤러 슬롯 매핑, 레인 기하·구분선·색, `ChartMode` 값 고정.

같은 기간 전체 `ctest`에서 7개(`BmsCompatibilityPlaybackTests`, `BmsDisplayTests`, `BmsUiTests`, `SevenManiaSkinBindingTests`, `SevenManiaSkinApplicationTests`, `BmsAccuracyRestartTests`, `SevenManiaDefaultHudImageTests`)가 실패했다. `BmsDisplayTests`와 `BmsAccuracyRestartTests`는 이 작업의 변경을 되돌린 상태에서도 같은 메시지로 실패했다. 나머지 5개는 변경 전 상태로 비교하지 않았다.

## 알려진 한계

- **5K와 7K 구분:** 11-16번 채널만 쓰는 `.bms`는 5K로 분류된다. BMS 형식상 5K와 6키 이하 7K를 사용 채널만으로 구분할 수 없다. 원본을 7K로 승격하지 않는다.
- **PMS 감지:** 확장자가 `.pms`일 때만 PMS로 분류한다. `.bms`로 저장된 PMS 배치(채널 16-19 사용 등)는 감지하지 않으며 채널 16-19, 26-29, 21은 PMS에서 버린다.
- **`PLAYER 2` 단독 채보:** 2P 채널만 있으면 10K(또는 7K 확장 채널이 있으면 14K)로 분류한다.
- **bmson:** `mode_hint`가 `beat-5k/7k/10k/14k`, `popn-9k` 외이면(예: `generic-nkeys`) "unsupported bmson mode"로 차단한다.
- **스킨 기어(덱):** 모드별 기어가 있는 스킨에서는 엔진의 단색 덱을 그리지 않는다(그리면 스킨의 7K 건반 텍스처를 가린다).
- **스킨 기어:** 기본 스킨은 5K/10K/14K/PMS 기어를 가진다(아래 "스킨 기어와 에디터"). 모드별 배치가 없는 스킨은 7K 기어를 숨기고 엔진 기본 덱만 보여 준다. 스킨을 쓰지 않을 때의 엔진 기본 덱은 아직 7K 건반 텍스처를 쓰지 않는 단색 버튼이다.
- **하이브리드 GPU 덱:** 비7K는 덱을 CPU로 그려 올리는 경로다. 성능은 측정하지 않았다.
- **기록·게이지:** 기록(`PlayRecord`)에 모드, 랜덤 옵션, 게이지 종류 필드가 없어 RANDOM 클리어와 일반 클리어가 같은 기록을 쓴다. 게이지 규칙은 모드와 무관하게 노트 수만 반영한다. DP/PMS 전용 게이지 규칙과 오토스크래치는 없다.
- **`SongGroup.mode`:** 한 곡 그룹에 SP/DP 채보가 섞여도 첫 차트의 모드만 가진다. 선곡 키 모드 필터는 Win32 호스트(`Main.cpp`)에서만 동작하고 C++/Rust 선곡 모델은 모른다.
- **설정 화면:** 키 설정 폴백 경고는 화면에 표시하지 않는다. 컨트롤러 설정 창은 2P 열 때문에 1040px로 넓어졌으나 화면에서 레이아웃을 확인하지 못했다.
- **PMS 구분선:** 구분선 기본값이 7K 기준(첫 줄만 켜짐)이라 PMS에서는 첫 버튼 옆에만 보인다.
