SevenMania 스킨 시스템 — 남은 구현 및 검증 목록
작성일: 2026-10-28
기준: 3.5차 초기 에디터와 4차 부분 구현(93776bc)까지의 구현 상태 문서.
이 파일은 작업 목록이다. 여기 적힌 기능을 이번에 구현하거나 검증했다는 의미는 아니다.

============================================================
1. 4차 애니메이션·이벤트 시스템의 필수 미구현 기능
============================================================

[ ] Tint RGB 색상 애니메이션
    현재 opacity 변화는 가능하지만 RGB Tint의 시간별 변화는 없다.
    매 프레임 이미지 디코딩 없이 GPU에서 처리하는 경로가 필요하다.

[ ] 스프라이트 시트 애니메이션
    현재 스프라이트의 정적 첫 프레임 표시와 메타데이터만 있다.
    프레임 영역/순서, FPS 또는 프레임별 지속 시간, 반복/일회성,
    재생 완료 후 유지/복원, 텍스처 재사용 및 UV/source 변경을 구현한다.

[ ] 키프레임 속성 확장
    현재 x/y, 균일 scale, rotation, opacity만 지원한다.
    width/height 직접 애니메이션과 필요한 축별 scale 지원을 확정한다.
    속성별 충돌 규칙을 전체 속성에 일관되게 적용한다.
    현재 같은 속성은 배열 뒤쪽의 활성 트랙이 우선한다.

[ ] 이벤트 중첩 정책
    현재 restart와 ignore만 지원한다.
    overlap의 최대 인스턴스 수, 합성/우선순위, 초과 시 처리,
    종료 인스턴스 회수와 빠른 연속 판정에 대한 제한을 구현한다.

[ ] 추가 게임 이벤트 연결
    현재 screen.enter와 판정 표시 경로의 judgement만 연결되어 있다.
    아직 연결되지 않은 후보:
    - screen.exit
    - combo.break
    - result.enter
    - result.clear
    - song.changed
    기존 엔진에서 확실히 읽을 수 있는 발생 지점과 의미부터 확정한다.
    제공할 수 없는 이벤트를 추정 계산으로 만들지 않는다.

[ ] 이벤트 데이터와 수명 정리
    이벤트 종류별 표시용 데이터와 발생 시점, 화면 전환 시 유효 범위,
    같은 이벤트의 연속 발생 처리 및 UI 소유 스레드 전달 규칙을 확정한다.
    스킨에서 게임 판정·점수·게이지에 쓰기 접근하는 경로는 만들지 않는다.

[ ] 게임 시간과 UI 시간 분리
    현재 steady_clock 기반 UI 경과 시간만 사용한다.
    게임 동기 효과의 시간 기준, pause/resume, 재시작·연습 구간 이동,
    화면 전환·리절트 진입 시 정리 정책을 구현한다.
    판정과 오디오 시간 계산은 변경하지 않는다.

[ ] 로더 단계의 애니메이션 전용 검증
    현재 트랙 검사는 renderer 준비 시 수행된다.
    SkinLoader 단독 호출에서도 잘못된 애니메이션을 판별하도록
    공통 검증 경로를 마련한다. 자료형, 지원 속성·트리거·정책,
    키프레임 범위/순서/개수와 오류 위치를 명확히 검사한다.

[ ] 완료 상태와 재그리기 최적화
    완료한 hold 트랙 때문에 불필요하게 UI 재그리기가 계속되는 문제를 정리한다.
    마지막 프레임은 정확히 반영하고, 정적인 완료 상태에서는 캐시를 재사용한다.
    화면 종료 및 스킨 교체 시 활성 상태와 예약된 작업을 정리한다.

============================================================
2. 에디터의 애니메이션 연동 — 미구현
============================================================

[ ] 애니메이션 목록 및 대상 요소 선택
[ ] 트랙 추가·복제·삭제·이름 변경
[ ] 키프레임 생성·선택·수정·삭제
[ ] duration, easing, loop, trigger, finish, 재시작/중첩 정책 편집
[ ] 재생·정지·재시작 및 시간 위치 이동
[ ] 편집한 애니메이션의 실시간 미리보기 루프
[ ] 게임과 동일한 공통 평가기를 사용하는 미리보기 연결
[ ] 애니메이션 편집 작업의 Undo/Redo
[ ] JSON/폴더 프로젝트/.semaskin 저장·재로드 왕복 검증
[ ] 필요시 간단한 타임라인 UI

현재 에디터는 extensions의 애니메이션 JSON을 보존할 수 있으나,
전용 애니메이션 편집 UI와 재생 루프가 구현된 상태는 아니다.

============================================================
3. 3.5차 에디터에서 남은 구현·보완
============================================================

[ ] 창 크기·고해상도·DPI 변화에 대응하는 반응형 배치
[ ] 작은 창에서도 툴바·속성·캔버스 조작 영역이 잘리지 않도록 처리
[ ] 요소 종류에 따라 관련 있는 속성만 표시
[ ] 속성 입력 즉시 반영 또는 적절한 디바운스 갱신
    현재는 '속성 적용' 버튼으로 반영한다.
[ ] 작은 속성 변경 시 전체 패키지 재검증/렌더러 준비를 줄이는 갱신 경로
    드래그 좌표 갱신은 이미 텍스처를 재사용한다.
[ ] 이미지 source rectangle 및 clip 전용 편집 UI
[ ] 스프라이트 시트 전용 편집 UI
[ ] 스킨 ID·이름·제작자·버전·설명·가상 해상도 등의 메타데이터 편집 UI
[ ] 앵커 확장 및 조작 규칙 정리
    현재 top-left / center / bottom-right의 위치 기준만 지원한다.
    회전 중심 규칙은 기존 게임 렌더러와 동일하게 유지한다.
[ ] 편집 모델과 Win32 GUI 코드 분리 등 유지보수 구조 보완
[ ] 프로젝트 pending/backup의 복구 안내 및 관리 UX 보완
    백업/임시 폴더는 현재 자동 삭제하지 않는다.

============================================================
4. 구현은 있지만 검증이 충분하지 않은 항목
============================================================
아래 항목은 '미구현'과 다르다. 동작 코드가 있더라도 전 조합의
자동/수동 검증이 끝나지 않았으므로 정상 동작 확정을 위한 검사 항목이다.

에디터 좌표·선택:
[ ] 50%, 100%, 200%에서 드래그의 실제 저장 좌표 비교
[ ] Pan 이후 선택·이동·크기 조절 좌표 비교
[ ] 회전된 요소의 선택 및 핸들 조작
[ ] 겹친 요소의 z/동률 선언 순서에 따른 선택
[ ] 잠금·숨김·복제·삭제·이름 변경·순서 변경의 조합
[ ] 속성 값과 캔버스 위치의 일치, 과도한 반올림 여부

에디터 이력·저장:
[ ] 이동/크기/속성/추가/삭제/순서 변경의 Undo/Redo 전 조합
[ ] 드래그 1회가 이력 1회로 기록되는지 검증
[ ] Undo 후 새 편집 시 Redo 분기 정리 검증
[ ] 저장 실패·교체 실패·폴더 교체 중 실패의 원본 보존/복구 검증
[ ] 기존 extensions/source/sprite 등의 보존과 재로드 비교
[ ] 이미지 누락·잘못된 JSON·반복 열기/닫기 및 자원 수명 검사 확대
[ ] 실제 게임과 에디터의 이미지·텍스트·클리핑·레이어 출력 비교

애니메이션·이벤트:
[ ] 실제 GPU 출력의 이동·크기·회전·투명도 시간별 픽셀 비교
[ ] Tint 및 스프라이트 구현 후 출력 검증
[ ] 실제 빠른 연속 판정의 시각 결과와 이벤트 손실/재시작 동작
[ ] restart/ignore/overlap 및 속성 충돌 조합
[ ] 반복·완료·복원·프레임 지연 및 화면 전환 정리
[ ] 게임 시간·일시정지 동기화
[ ] 에디터 미리보기와 패키지 저장 후 게임 출력 비교
[ ] 장시간 플레이의 프레임 시간·CPU/GPU 메모리 추이
[ ] 실제 GPU 장치 손실과 복구

이미 확인한 범위:
- 기본 BmsPlayer 및 초기 에디터 빌드
- 에디터 스모크: 새 문서, 텍스트 추가, 렌더러 준비, 좌표 갱신,
  패키지/폴더 저장·재로드
- 애니메이션 평가기의 보간·반복·완료·4개 주사율 시간 평가,
  기본 JSON 및 잘못된 duration 검사
- 기존 스킨 관련 자동화 검사
이 결과를 모든 기능의 완료·장시간 안정성 증명으로 확대 해석하지 않는다.

============================================================
5. 스킨 시스템 전체의 후속 확장 — 현재 단계 필수와 구분
============================================================
아래는 아직 없는 기능이지만, 모두가 4차 완료 조건인 것은 아니다.

[ ] 관리 폴더에 스킨 설치/복사 및 여러 설치 스킨의 목록 관리
    현재는 외부 파일 한 개의 경로를 저장해 직접 사용한다.
[ ] 화면별로 서로 다른 패키지를 고르는 사용자 설정 UI
    내부 화면별 선택 구조와 현재 단일 패키지 적용 UI를 구분한다.
[ ] 기존 UI·노트·레인·버튼의 전면 스킨화
    현재 적용은 기존 화면에 이미지·텍스트를 덧그리는 방식이다.
[ ] 텍스트 자동 줄바꿈·말줄임·스크롤, 숫자 이미지 폰트
[ ] 개별 이미지 파일 시퀀스 애니메이션
[ ] 세부 판정 enum/판정별 누계 등 추가 데이터 바인딩
    현재 play.judgement는 HUD 표시 문자열이며 PGREAT/GREAT가 구분되지 않는다.
[ ] DDS 등 추가 이미지 형식
[ ] LR2 스킨 변환기
[ ] Core/일반 디자인 스킨 제작

이번 단계에 추가하지 않을 기능:
- 영상 재생
- 사용자 임의 스크립트 실행
- 온라인 스킨 마켓/다운로드
- 고급 셰이더 효과 시스템

============================================================
6. 권장 진행 순서
============================================================
1) 공통 애니메이션 모델·로더 검증·시간/이벤트 의미 확정
2) 시간/완료/화면 전환 정리와 회귀 테스트 보완
3) Tint RGB 및 스프라이트 재생 구현
4) 실제 게임 이벤트 추가 및 연속 이벤트z 정책 검증
5) 에디터 애니메이션 편집·재생·저장 연결
6) 에디터 배치·속성 갱신·저장 복구 UX 보완
7) 실제 게임/에디터 출력 비교와 장시간 성능 검증
