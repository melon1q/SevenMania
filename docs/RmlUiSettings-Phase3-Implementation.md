# 설정 창 RmlUi 3단계

2026-10-26 · `codex/rmlui-settings-ui-test`

## 적용 범위

설정창을 열면 새 RmlUi **기타** 페이지를 표시한다. `Assets/UI/settings.rml`과 `settings.rcss`에 카테고리 탐색, 섹션 카드, 상태 표시, 고정된 닫기 영역을 구성했다. 기존 설정 HWND 안에 자식 RmlUi 호스트를 넣으므로 페이지 전환 때문에 별도 설정창이 중복 생성되지 않는다.

첫 실제 연결 항목은 **시스템 자원 보기**다. 요약 페이지 전체를 먼저 이관하지 않았다.

- 체크박스는 `SettingsController`의 기존 `ID_RESOURCE_USAGE` 명령을 메인 스레드 큐에 전달한다.
- 적용·저장은 기존 C++ 경로가 수행한다. `System/ShowUsage` 값과 실제 실행 상태가 원본이다.
- 자원 오버레이와 플레이 화면 왼쪽 하단 FPS·BPM·배속이 같은 값에 연결된다.
- 적용 후 UI를 실제 값으로 동기화한다. 프로그래밍 방식으로 체크 상태를 맞출 때는 새 변경 명령을 발생시키지 않아 피드백 루프를 막는다.
- 폼 컨트롤은 `change` 이벤트로만 값을 전달한다. 체크박스 클릭 전/후 값이 각각 중복 저장되는 방식은 사용하지 않는다.

기존 Win32 컨트롤을 새 UI의 값 저장소로 읽지 않는다. 새 페이지가 표시되는 동안 숨겨진 네이티브 컨트롤을 갱신하지 않으며, 기존 페이지로 돌아갈 때 C++ Snapshot으로 화면 값을 다시 맞춘다.

## 기존 페이지 사용

요약·게임플레이·그래픽·사운드 버튼을 누르면 **같은 설정 HWND**에서 기존 Win32 페이지로 전환한다. 이때 RmlUi 자식 화면은 가리고 기존 본문과 컨트롤을 표시한다. 반대로 기타 카테고리로 돌아오면 네이티브 본문·탐색 버튼·닫기 영역을 모두 가리고 RmlUi 페이지를 표시한다. 두 화면을 겹쳐 그리지 않는다.

새 기타 페이지의 **기타 고급 설정 열기**를 누르면 배경 선택·CPU/메모리 상한 등 아직 이관하지 않은 기존 기타 항목을 조작할 수 있다. 네이티브 기타 페이지에서 바꾼 값도 다시 RmlUi 페이지를 열 때 반영된다.

**기존 설정창 사용**은 해당 설정창 세션 동안 RmlUi 페이지를 끄고 네이티브 설정을 사용한다. 설정창을 닫았다가 다시 열면 새 페이지를 다시 시도한다. F9 입력 실험 창은 계속 사용할 수 있다. RmlUi 페이지의 F9도 부모 설정창에 전달한다.

## 창 크기와 입력

헤더·푸터는 고정하고 본문만 스크롤한다. 최소 780×400 창에서도 닫기 영역이 화면 안에 남도록 flex 높이와 작은 창용 배치를 명시했다. 카테고리 탐색은 작은 창에서 간격을 줄이며 필요한 경우 스크롤할 수 있다.

RmlUi 자식 창의 입력은 기존 IsDialogMessage 경로에서 제외한다. 카테고리 전환·닫기는 메시지를 큐에 넣어 RmlUi 이벤트 처리 중 문서를 파괴하지 않는다. Esc는 설정창 전체를 닫고 기존 정책대로 적용된 값을 보존한다. 네이티브 페이지로 전환하거나 오류에서 복귀하면 해당 카테고리 버튼으로 포커스를 돌린다.

## 실패 시 복귀

- RmlUi 초기화/문서 로드 실패, 외부 RCSS 누락, 필수 컨트롤 누락 시 기존 기타 페이지를 사용한다.
- 로드 전후의 RmlUi 경고·오류 수를 확인해 RML/RCSS 해석 오류도 복귀 조건으로 처리한다.
- 설정 세션을 새로 열 때 외부 스타일시트를 다시 해석한다. 잘못된 스타일 캐시 때문에 두 번째 열기에서 검증을 우회하거나, 수정된 스타일을 계속 무시하지 않도록 했다. 이미 열린 다른 문서는 그대로 유지한다.
- 렌더링 등 세션 중 호스트 오류는 부모 창에 복귀 메시지를 보내고 해당 자식 문서를 정리한다. 기존 화면을 다시 표시해 오류를 안내한다.
- 복귀 시 실행 상태나 INI를 초기화하지 않는다. 오류 전에 적용한 값은 유지한다. 같은 설정창 세션에서는 실패한 페이지를 반복 생성하지 않는다.

## 검증

기본 Release 구성의 관련 테스트 7개가 통과했다. RmlUi 전체 OFF 구성의 네이티브 기준 테스트와 설정창만 ON인 구성의 3단계 테스트도 통과했으며, 마지막에는 기본 ON 구성으로 복원해 제품 실행 파일을 빌드했다.

`BmsSettingsPhase3Tests`는 합성 INI 복사본과 실제 Win32/RmlUi 호스트를 사용한다. 개인 설정·곡 폴더·오디오 출력 장치는 사용하지 않는다.

- 실제 체크박스 클릭 → 실행 값/INI의 OFF·ON 확인.
- `drawGameScreen`의 왼쪽 하단 정보 영역을 비교해 같은 설정으로 FPS/BPM/배속 표시가 바뀌는지 확인.
- 같은 부모 HWND 유지, 네이티브 본문과 새 페이지의 배타적 표시, 기존 사운드·기타 페이지 접근과 값 동기화 확인.
- 작은 창의 닫기 버튼 영역이 client 안에 있는지 확인하고 화면 캡처 생성.
- 설정 다시 읽기·창 재열기로 값 유지 확인.
- 세션 중 복귀 메시지·사용자의 기존 UI 선택, RCSS 누락/문법 오류/오류 상태 재열기, RML 누락/필수 컨트롤 누락과 정상 자산 복구 확인.
- 곡 목록 Context를 유지한 채 설정 스타일시트를 다시 읽어도 목록이 계속 렌더링되는지 확인.

기존 0단계 네이티브 기준 테스트는 새 페이지를 끄고 계속 실행한다. 다른 카테고리의 기능 보존을 새 UI 성공 여부와 분리해 확인하기 위한 테스트 설정이며 실제 게임의 기본값은 새 페이지 사용이다.

```powershell
cmake -S . -B build-rmlui-song-list
cmake --build build-rmlui-song-list --config Release --target BmsPlayer BmsSettingsPhase3Tests
ctest --test-dir build-rmlui-song-list -C Release --output-on-failure -R "BmsSettings.*Tests|BmsRmlSettingsHostTests|BmsRmlSongList.*Tests|BmsDisplayTests"
```

합성 화면은 `build-rmlui-song-list/Validation/SettingsPhase3/`의 `settings-other-on.png`, `settings-other-off.png`, `settings-small.png`에 저장된다. 이 테스트는 물리 입력·실제 다중 모니터 DPI 이동·GPU 장치 장애를 모두 재현하는 시험은 아니다. 런타임 오류 복귀 흐름은 부모 복귀 메시지로 검증했다.

제품 실행 파일은 기존 `build-rmlui-song-list/Release/BmsPlayer.exe`를 업데이트한다. 다음 4단계에서 일반 설정을 카테고리별로 옮긴 뒤, 임시 네이티브 페이지 연결을 정리한다.
