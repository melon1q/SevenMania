# DefaultReference 기본 적용과 로딩 재시도

기본 선택(설정 경로가 비어 있음)은 실행 파일 옆 Assets/Skins/DefaultReference.semaskin을 사용한다. 기본 BmsPlayer와 적용 통합 테스트 빌드 시 이 파일을 배치한다. 사용자 지정 파일 경로가 저장되어 있으면 해당 파일을 우선한다. 설정의 '기본 화면으로 복원'은 이제 네이티브 정보 화면으로 되돌아가는 대신 DefaultReference 패키지를 다시 읽는다.

곡 선택·리절트는 기존 정보 화면을 먼저 그리지 않고 검은 바탕 위에 스킨을 출력한다. 플레이의 기존 문자 HUD는 정상 플레이 중 중복 출력하지 않는다. 노트·기어·곡 목록·일시정지 메뉴 등 아직 스킨 포맷이 대체하지 못하는 기능은 기존 엔진이 유지한다. 이는 완전한 UI/노트 스킨화와는 다르다. DefaultReference의 참고값·폰트·플레이 HUD 배치 제한은 docs/DefaultSkinTemplate.md를 따른다.

파일 검증/리소스 준비 실패 시 이전 스킨을 계속 표시하는 정책을 제거했다. 선택 스킨을 비우고 메인 화면을 검게 유지하며 네이티브 자식 컨트롤을 숨긴다. Windows UI 타이머로 1초 간격의 재시도를 계속한다. 무한 while 루프나 Sleep으로 UI 스레드를 점유하지 않는다. 재시도 성공 시 타이머를 해제하고 화면과 필요한 컨트롤을 복원한다. 실패 상태에서도 설정 창을 열어 다른 파일을 선택할 수 있다.

종료 시에는 스킨을 재적용하지 않고 자원과 타이머만 해제한다. 직접 선택한 파일이 잘못되었을 때도 해당 파일을 현재 세션에서 재시도하며, 실패한 경로를 성공한 설정인 것처럼 저장하지 않는다. 부분 패키지에 없는 화면은 더 이상 네이티브 정보 화면으로 폴백하지 않으므로 호환되는 화면을 포함한 패키지를 사용해야 한다.

검증: 기본 실행 파일 빌드, 적용 통합 테스트의 기본 패키지 복원, 로딩 실패의 빈 화면/재시도 상태, 누락 파일을 복구한 뒤 타이머를 통한 재적용을 검사한다. 실제 파일 선택기 조작 및 장시간 플레이 전체를 수동 점검한 것은 아니다.

최종 확인: 기본 BmsPlayer.exe 빌드 성공. 로더/렌더러/바인딩/적용/애니메이션의 스킨 관련 테스트 5종 통과. 적용 테스트는 실패한 패키지 상태에서 검은 픽셀을 확인하고, 해당 파일을 복구한 뒤 WM_TIMER 재시도로 성공 상태에 복귀하는 것을 확인했다.
