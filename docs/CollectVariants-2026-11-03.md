# 같은 곡 차분 모아 보기

## 사용법

설정 → 기타 → 곡 라이브러리 → 채보 표시에서 **같은 곡 차분 모아 보기 (SP / DP)**를 선택한다. 한 곡 항목에서 기존 ← / → 키로 차분을 바꾼다.

기존의 그룹 보기(음원 기준) 및 개별 채보 보기도 유지했다. 현재 사용자의 선택값을 강제로 변경하지 않으므로 새 모드는 직접 선택해야 한다.

## 원인과 기준

실제 Oekaki 캐시를 조사했을 때 같은 물리적 곡 폴더 안에서도 DP 차분의 음원 경로 집합은 1,258개, SP 차분은 1,259개였다. 기존 엄격한 그룹 식별은 폴더·기본 곡명·음원 집합을 사용하므로 SP/DP가 분리된다. 개별 보기에서는 각 차분도 모두 별도 항목으로 표시된다.

새 모드는 같은 실제 디렉터리와 정규화된 기본 곡명이 같으면 음원 집합·SP/DP 키 모드 차이와 관계없이 하나로 묶는다. 제목의 기존 차분 접미사 정규화 기능을 재사용한다. 서로 다른 폴더의 동명 곡이나 같은 폴더의 다른 곡명은 합치지 않는다. 따라서 동명이나 리믹스 등을 별개로 유지하려면 기존 음원 기준 그룹 보기를 사용할 수 있다.

실제 파일을 이동/복사하거나 캐시의 그룹 키를 덮어쓰지 않는다. 실제 채보 경로와 차분별 플레이 기록, 원래 메타데이터를 보존하며 보기 전환 시 메모리 모델만 재구성한다. 기존 선택 채보 경로 복원 경로도 유지한다.

## 구현

- `SongLibrarySources`: 기존 INI `[SongLibrary] CollectVariants`에 선택 상태를 추가 저장. 기존 IndividualCharts 항목 유지.
- `SongGrouping`: 선택적으로 음원 집합 조건을 제외하는 식별 함수 확장. 기본 동작은 기존의 엄격한 기준.
- `SongSelection.h/.cpp`, `SongSelectionRust.cpp`: 동일한 모아 보기 정책을 적용. Rust ABI나 파서 변경 없음.
- `Main.cpp`: 모델 재구성 시 정책 전달.
- `SettingsRmlPage.inl`, `Assets/UI/settings.rml`: 기타 탭 선택지와 조작 안내 추가.

## 검증

- 합성 Oekaki SP/DP 6개를 서로 다른 음원 집합으로 구성: 엄격한 그룹 2개 → 모아 보기 1개, 6차분 보존 및 순환 전환 확인.
- 같은 폴더의 다른 제목과 다른 폴더의 동명 곡이 합쳐지지 않음 확인.
- 개별 보기 우선 동작, 전체 채보 인덱스 누락/중복 방지 확인.
- 실제 캐시: 788개 채보 모두 보존. Oekaki가 들어 있는 두 물리적 폴더에서 각각 6차분짜리 항목 하나로 묶임 확인. 두 폴더를 하나로 합치는 처리는 하지 않음.
- BmsLibraryTests / BmsSongSelectionTests / BmsSongLibraryUiTests 통과. 실제 RmlUi 선택 이벤트와 설정 저장/재로드 확인.
- Rust 선곡 모델과 C++ 대체 모델의 BmsSongSelectionTests 모두 통과.
- 기본 BmsPlayer.exe Release 빌드 성공, 같은 게임 바이너리 SevenMania.exe 업데이트.

수동 인게임 플레이는 수행하지 않았다. 런처는 실행 중인 파일 잠금으로 첫 빌드의 교체가 막혔으며, 사용자의 종료 후 재빌드가 필요하다. 기존 런처도 알려지지 않은 CollectVariants 키를 삭제하지 않지만 최신 공통 설정 코드 반영 여부는 별도 구분한다.

로그: `build-rmlui-song-list/Validation/group-variants-*.log`. 빌드 산출물과 실제 사용자 캐시는 커밋하지 않는다.
