# Random BGA / STOP 동기화 조사 (2026-10-22)

실제 Random 채보 `_random_s2/s3/s4.bms`, `_random_d2/d3/d4.bms`를 읽기 전용으로 검사했다. 곡 파일은 수정하지 않았다. DP 채보는 타임라인만 검사했으며, 지원 플레이 모드를 추가한 것은 아니다.

## 원인과 수정

- 채보의 `#BMP01 __bga.mpeg` 시작점은 첫 마디의 `41/64` 위치다. BPM 132에서 약 **1.164772727초**에 해당한다. 플레이어는 같은 폴더의 `__bga.mp4`를 우선 선택했지만, 확장자가 달라 지정된 이벤트를 찾지 못하고 첫 음원 시각인 0초부터 영상을 진행했다. 같은 폴더·파일 이름의 대체 영상도 원본 영상의 시작 이벤트를 따르도록 변경했다. 다른 폴더의 영상과 정지 이미지는 일치 대상으로 취급하지 않는다.
- Random은 BPM **99132**와 반복 STOP을 조합한다. 각 채보에는 **572개**의 양수 STOP 구간이 있다. 기존 노트 좌표는 시간 차이에만 비례했기 때문에 이 정지 효과를 표시하지 못했다. BPM에 따른 이동과 STOP의 정지를 담은 별도 스크롤 타임라인을 추가했다. 오디오, 판정, 영상은 실제 채보 시간을 유지한다.
- 같은 박자의 STOP보다 노트·BGM·BGA를 먼저 처리한다. 해당 박자의 BPM 변경은 STOP 길이 계산에 반영한다. `#STOP0A`처럼 문자가 포함된 타이밍 ID도 정의와 동일하게 정규화한다.
- 이미지 BGA 이벤트는 채보 시간, 단독 영상은 시작 이벤트를 뺀 영상 시간으로 처리한다. 영상 시작 시각은 곡을 읽을 때 계산한다.

STOP 시작점에서 노트를 처리하는 순서는 [bmson 공식 사양의 BMS 호환 처리 규칙](https://bmson-spec.readthedocs.io/en/master/doc/#order-of-processing)을 참고했다.

## 검증

- 실제 6개 채보의 노트·BGM·BGA 이벤트 **12,836개**를 별도의 유리수 기반 계산과 비교했다. 최대 시간 차이는 약 `6.6e-13`초였다.
- 각 채보의 572개 STOP에서 노트 좌표가 유지되고 영상의 실제 시간은 계속 진행함을 확인했다.
- 파서 회귀 테스트: BPM 변경과 STOP 동시 발생, 연속 STOP, STOP 시작점의 음원·노트·BGA, STOP을 가로지르는 롱노트, BPM 99132, 문자 ID, MPEG→MP4 대체 및 잘못된 대체 경로 제외.
- CPU/GPU 렌더링 테스트: STOP 전·중·후의 실제 노트 픽셀 위치 비교.
- Random의 실제 MP4로 첫 프레임 준비, 시간 이동, 되감기 검사.
- mimalloc·oneTBB·하이브리드 구성과 라이브러리/Reflex 없는 기본 구성의 Release 빌드 및 회귀 테스트.

이는 채보 시각·디코더·렌더링의 자동 검증 결과다. 외부 실행기의 화면·소리를 녹화해 비교하거나 사용자의 출력 장치 지연을 측정한 결과는 아니다.

## 2026-10-25: MPEG가 존재하지만 디코딩되지 않을 때 BGA 누락

Random 폴더의 `_play_like_you_never_did_before.zip`은 추가 `_random_s0-1.bme`~`_random_s0-7.bme`를 담고 있었다. 실제 선택되는 SP/DP 6개 `.bms`와 `__bga.mpeg`, `__bga.mp4`는 이미 폴더에 풀려 있었다. ZIP은 이번 누락 원인이 아니다. 압축 해제나 원본 파일 변경은 하지 않았다.

이 장비에서 실제 `__bga.mpeg`는 VideoBga가 열지 못했고, `__bga.mp4`는 첫 프레임·1초 이동·되감기를 정상 처리했다. BgaVideoLayers는 명시된 MPEG의 준비가 실패해도 해당 BMP 인덱스가 선언되었다고 판단하므로, 단독 fallbackVideo 경로가 실행되지 않았다.

`BgaVideoLayers::prepare`에서 원래 파일을 우선 시도하고, 준비 실패 시 **같은 디렉터리·같은 stem**의 다른 영상 확장자를 순서대로 재시도한다. MP4, M4V, MOV, WMV, AVI, MPEG, MPG, M1V, M2V를 대상으로 하며, 정상적인 원본 영상은 대체하지 않는다. 다른 이름의 영상을 임의로 사용하는 것은 금지한다. 모든 후보가 실패한 경우에만 실패 개수를 증가시킨다. 원래 BMP ID, 레이어, 이벤트 시작 시각, 반복 시 재시작 규칙은 그대로 유지한다. 취소 중에는 다음 후보를 열지 않는다.

검증:

- 손상된 MPEG + 같은 이름의 정상 AVI 샘플: 준비 성공, 시작 전 비표시, 이벤트 기준 시간 진행, 동일 ID 반복 시 재시작.
- 다른 이름의 정상 동영상으로 잘못 대체하지 않음, 준비 취소 처리.
- 실제 Random SP/DP 6개 채보: BGA 준비 실패 0개, 시작 1.164772727초, 시작 전 비표시, 0/1/10초 요청 및 되감기 성공.
- 하이브리드 구성 Release의 비 UI 회귀 테스트를 실행했다. 수동 장시간 플레이나 외부 장치의 오디오/화면 지연을 실측한 결과는 아니다.
- 로그: `build-result-fade/random-mpeg.log`, `random-mp4.log`, `_random_*-bga.log`, `random-regression.log`.
