# SevenMania 네이티브 스킨 기반: 설계 결정

1차 범위는 `.semaskin` ZIP 읽기, 엄격한 검증, 공통 데이터 모델, 메모리 내 등록과 화면별 선택이다. 기존 렌더링·게임·입력·오디오·BMS 해석 경로에는 로더 호출을 넣지 않는다.

## 조사와 재사용

- `bms_core`와 `bms_song_selection`은 기존 게임 경로다. 새 모듈은 별도 정적 라이브러리로 구성한다.
- `src/JsonValue.h`의 자료형과 C++ 파서를 재사용한다. 기존 파서를 수정하지 않고 UTF-8, 중복 키, 유니코드, 크기·깊이·노드 제한을 별도 검사한다.
- 일반 ZIP 로더는 없다. 이미 체크아웃된 `third_party/freetype/src/gzip`의 zlib inflate/CRC 소스를 독립 타깃으로 빌드한다. 새 외부 다운로드나 영상 라이브러리는 도입하지 않는다.
- 이미지 메타데이터는 Windows WIC로 검사한다. 렌더러나 GPU 객체를 생성하지 않는다.

## 경계

- 컨테이너 계층은 ZIP 경로·압축·크기·CRC를 검증하고 바이트를 반환한다. 디스크 추출은 하지 않는다.
- 공통 모델은 manifest, 자원 ID와 불변 바이트, 화면, 요소다. ZIP 엔트리나 LR2 문법에 의존하지 않는다.
- `SkinLoader::prepare`는 컨테이너 없이 만든 모델도 동일하게 검증한다. 미래 LR2 변환기는 이 경로를 사용한다.
- `SkinManager`는 검증된 불변 스냅샷을 등록하고 화면별로 선택한다. 실패는 등록/선택 상태를 바꾸지 않는다. 미지원 화면은 빈 결과를 반환해 호출자가 기존 기본 화면을 유지할 수 있다.

저장 설치 UI, 기존 화면 스킨화, 실제 디자인, 텍스처 업로드, 애니메이션 실행과 LR2 변환은 이번 범위 밖이다. 구체적인 v1 규격·제한과 검증 결과는 구현 후 별도 문서에 기록한다.
