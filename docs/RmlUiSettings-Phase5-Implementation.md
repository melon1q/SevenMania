# RmlUi 설정 5단계

2026-10-27 / `codex/rmlui-settings-ui-test`

## 구현

- 선택 곡의 큰 난이도 숫자는 곡 목록과 동일한 `songDifficultyColor`를 사용한다. 채보 난이도 분류 및 기존 레벨 색상 규칙이 함께 적용된다.
- 새 게임플레이 페이지에 기어 위치, 판정선·콤보·판정 텍스트 위치, 플레이 화면 미리보기, 키 지정·취소·기본 키 복원을 연결했다.
- 키 지정은 기존 `normalizedKey`·예약 키·중복 검사·8키 일괄 저장 경로를 재사용한다. 메시지 루프에서 RmlUi와 대화상자 탐색보다 먼저 물리 키를 처리한다. 문자 메시지와 Alt 입력은 레인 지정으로 전달하지 않는다. 키 해제 대기, 반복 입력 차단, Escape 취소를 유지한다.
- 키 지정 도중 카테고리 변경, 포커스 상실, 취소 메시지, 설정 변경, 창 종료 시 미완성 배치를 폐기한다. 화면의 안내 문구와 키 요약도 실제 상태로 갱신한다.
- 미리보기는 기존 게임 렌더러와 오버레이를 사용한다. 버튼으로 켜고 끄며 값 변경 후 다시 그린다. 카테고리 변경, 설정/게임 창 크기 변경, 비활성화, 창 종료 때 숨긴다. 설정 창을 옆으로 이동하면 원래 게임 창의 미리보기를 함께 볼 수 있다.
- 그래픽 페이지에 화면 모드·해상도·GPU·DirectComposition·저지연 선택을 추가했다. 사운드 페이지에는 출력 버퍼를, 기타 페이지에는 CPU 우선순위·CPU/메모리 상한을 연결했다. 요약에도 화면 모드를 추가했다.
- 장치 명령은 RmlUi 이벤트에서 직접 실행하지 않고 기존 SettingsController 큐를 거쳐 적용·저장한다. GPU 관련 종속 항목과 Reflex 지원 여부에 따라 컨트롤을 비활성화한다. 적용 후 실제 Snapshot으로 모든 페이지를 동기화한다. 기존 전체화면 실패 시 보더리스 복귀와 오디오 초기화 경로를 유지한다.
- 판정선 범위는 현재 게임 창 높이로 계산한다. 위치 항목의 표시는 `%` 대신 `px`를 사용한다.

## 입력과 접근성

현재 설정 항목은 선택지·체크·수치·버튼으로 구성되며 직접 문자를 입력할 필요가 없다. 따라서 별도 IME 필드를 추가하지 않았다. 물리 키 지정은 문자 입력과 분리한다. 기존 입력 호스트의 IME 실험 검증은 유지한다.

Tab/Shift+Tab, 화살표, Space/Enter와 포커스 스크롤을 사용한다. RmlUi가 Win32와 동등한 스크린리더·시스템 고대비 지원을 제공한다고 가정하지 않는다. 해당 지원이 필요하면 하단의 `기존 설정창 사용`으로 Win32 화면을 사용할 수 있다. 실제 보조기기나 물리 모니터의 고배율 전환 검증은 이번 자동 검사에 포함하지 않는다.

## 검증

`BmsSettingsPhase5Tests`는 합성 INI와 실제 Win32/RmlUi 창을 사용해 다음을 확인한다.

- 새 키 지정 버튼, 예약 키/중복/Alt 거부, 키 해제 대기, Escape·포커스 상실·카테고리 변경 취소, 전체 배치 저장과 기본값 복원
- 기존 미리보기 생성, 위치·기어 값 적용, 카테고리/크기 변경/닫기 후 정리
- GPU 전환, 보더리스→창화면, 자동 해상도, DirectComposition·저지연 OFF 적용 뒤 RmlUi 유지 및 요약 일치
- 잘못된 해상도 요청 실패 후 기존 값 유지, 출력 버퍼 UI와 엔진 요청값 일치, 저장 후 재열기

전체화면 디스플레이 모드 변경과 지원 GPU에서 Reflex ON의 실제 지연 개선, 모든 오디오 장치의 출력 재개는 자동 검사로 보장하지 않는다. 기존 장치 처리 경로를 재사용하며 실제 장비별 확인은 필요하다. 오디오 버퍼 값은 엔진의 요청값으로, 장치가 제공하는 실제 지연 시간과 같다는 의미가 아니다.

기존 곡 목록 픽셀 비교가 1회 불일치하여 단독 재검사로 통과한 뒤, 선택 재그리기 검사가 제목 스크롤 시간 차이를 비교하지 않도록 캡처 시간을 초기 정지 구간으로 고정했다. 스크롤 동작 자체의 검사는 별도 렌더러 테스트에서 유지한다.

기본 배포 파일은 `build-rmlui-song-list/Release/BmsPlayer.exe`로 유지한다. 개인 곡과 개인 INI는 테스트에 사용하지 않는다. 6단계의 기존 Win32 화면 제거는 수행하지 않았다.

검증 결과: 관련 테스트 8개 전체 통과. RmlUi OFF 구성에서도 기존 설정 기준 테스트를 빌드하고 통과했다. 게임플레이 위치/키 카드와 그래픽 화면 캡처를 확인했다.
