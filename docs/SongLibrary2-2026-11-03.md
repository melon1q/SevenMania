# SevenMania Song Library 2.0 구현 보고서

## 1. 결과와 사용 방법

곡 라이브러리 핵심 기능을 구현하고 기본 `build-rmlui-song-list/Release/BmsPlayer.exe`를 업데이트했다. **전체 회귀 검증 완료 상태는 아니다. 최종 관련 테스트 14개 중 곡 목록 재그리기 검사 1개가 실패했다.**

설정 → **기타 → 곡 라이브러리**에서 다음을 사용할 수 있다.

- BMS 폴더 추가, 등록 목록과 연결 상태 확인, 등록 해제
- 선택한 폴더 재검색, 전체 새로고침, 진행 상태 확인
- 스마트 탐색 / 원본 폴더 탐색
- 그룹 보기 / 개별 채보 보기

기존 F2는 복사 없는 라이브러리 등록으로 연결하고, F5는 캐시를 전부 삭제하지 않는 증분 검증으로 변경했다. 곡 선택 화면에 Explorer 폴더를 드롭하면 등록한다. BMS 파일을 선택하거나 드롭하면 **그 파일의 부모 폴더를 등록**한다. 단일 파일만 복사하거나 즉시 재생하지 않으며, 같은 폴더의 다른 채보와 공유 리소스도 원래 위치에서 사용한다. 플레이·로딩·리절트 중 드롭은 거부한다.

## 2. 조사 결과와 이전 구현의 문제

- 기존 `SongLibrary`에는 파일 검색, 가져오기, 메타데이터 전용 스캔이 있었다. 게임의 등록 경로는 가져오기/복사를 거쳐 기본 Songs만 스캔했다.
- `SongMetadataCache`는 이미 파일 크기·수정 시각·부모 디렉터리 수정 시각에 따라 증분 검증하고, 빠른 스냅샷과 손상 시 재분석을 제공했다. 이를 재사용했다.
- 폴더 자동 생략 조건이 `groupCounts[directory] == 1`에 의존했다. 같은 말단 디렉터리의 채보가 제목/오디오 리소스 차이 때문에 여러 그룹이면 폴더가 남았다.
- C++/Rust 그룹 식별은 실제 디렉터리·정규화 제목·음원 리소스 식별을 사용한다. 빈 리소스 집합은 보수적으로 실제 채보 경로로 분리한다. 따라서 곡 그룹 수를 디렉터리 표시 규칙으로 쓰면 안 된다.
- 백그라운드 스캔 결과 반영 시, 선택 항목이 폴더라면 저장된 탐색 위치를 다시 읽었다. 스캔 도중 이동한 현재 위치가 과거 위치로 되돌아갈 수 있어 이 재복원을 제거했다. 시작 시 복원은 유지한다.
- 기록은 기존 `normalizedRecordPath`와 기록 파일을 사용한다. 미리듣기는 기존 `SongPreview`, 선택 BGA 보강은 기존 worker를 사용한다. 플레이 진입 시 원본 채보를 다시 파싱하는 경로도 유지한다.
- FramePacer·Reflex·오디오 타이밍·판정·컨트롤러 처리 자체는 수정하지 않았다.

## 3. 경로와 두 탐색 방식

| 개념 | 구현 |
|---|---|
| 실제 채보 경로 | 기존 `Chart::path`, 변경하지 않음 |
| 실제 디렉터리 | `Chart::path.parent_path()` |
| 표시 부모 | `SongFolderNavigation::displayParents_` / `displayParent()` |

스마트 탐색은 하위 채보가 없는 말단 채보 디렉터리의 곡들을 한 단계 위에 표시한다. 곡 그룹이 여러 개라도 각각 독립된 곡 항목으로 노출한다. 원본 파일이나 폴더는 이동하지 않는다.

중간 분류 폴더는 유지한다. 직접 채보와 더 깊은 채보가 함께 있는 혼합 디렉터리는 폴더로 보존하고, 그 안에 직접 채보와 하위 말단 채보를 함께 표시한다. 등록 루트의 직접 채보는 루트에 둔다. 스마트 모드로 전환하면서 현재 말단 폴더가 숨겨지는 경우 표시 부모로 이동한다.

원본 탐색은 같은 `gCharts`와 폴더 목록으로 실제 디렉터리 단계들을 표시한다. 모드 변경에 BMS 전체 재파싱이나 별도 데이터베이스 생성은 없다. 실제 폴더 목록 중 빈 폴더/미디어 전용 폴더는 백그라운드 디렉터리 조사 후 제공된다.

외부 루트는 기본 홈의 `LibraryRoot` 항목으로 표시하고, 루트에서 뒤로 가면 기본 홈으로 돌아온다. 중첩 등록은 유지하되 검색 루트를 상위 경로로 합치고, 대소문자를 무시한 정규화 실제 경로로 채보 중복을 제거한다. 기본 Songs가 외부 등록 경로의 하위에 있는 경우에도 기본 홈과 외부 경로에서 채보가 중복 표시되지 않게 소유 루트를 구분한다.

기존 은색·회색 스타일과 청회색 상위 이동 스타일을 유지했다. 곡/폴더/상위 이동/ALL SONGS/라이브러리 루트를 유형으로 구분하며 `DIR`, `LIB`와 제목을 분리한다. ALL SONGS는 곡 정렬에 포함하지 않는다.

## 4. 다중 등록·캐시·비동기 관리

- `SongLibrarySources`: 기본 Songs 자동 등록, 외부 경로 추가/제거, 중복 판별, 설정 저장, 캐시 위치 결정.
- 설정 파일의 `[SongLibrarySources]`에 경로 목록을 저장한다. 기존 INI 인코딩을 바꾸지 않도록 `utf16:` 뒤 ASCII 16진수로 경로를 저장한다. ANSI INI에서도 한국어·일본어 경로를 복원한다. 고정 등록 개수 배열은 없으며 실제 상한은 INI/API와 자원 제약을 따른다.
- `[SongLibrary]`의 `OriginalFolders`, `IndividualCharts`에 보기 설정을 저장한다. 알 수 없는 기존 설정과 플레이 기록은 유지한다.
- 기본 캐시는 기존 `Songs/.sevenmania-index/*.meta`를 재사용한다. 외부 캐시는 `Songs/.sevenmania-index/sources/<정규화 루트 해시>/*.meta`에 둔다. 외부 곡 폴더에 캐시를 쓰지 않는다.
- 메타데이터 바이너리 버전 `0x534D434143480002`는 유지한다. 저장 위치와 원본 경계만 분리했으므로 기존 기본 캐시를 읽을 수 있다. 잘못된 버전/손상/변경된 파일은 기존 재분석 경로로 복구한다. SQLite는 추가하지 않았다.
- 시작 시 캐시 스냅샷으로 채보 기반 탐색 계층을 만들고, 별도 worker가 추가·변경·삭제를 검증한다. 캐시가 없으면 전체 인덱싱한다. 캐시 기록 실패는 파싱/선곡을 막지 않는다.
- 단일 새 루트 등록 또는 선택한 폴더 재검색은 그 루트만 조사하고 다른 채보·폴더 목록을 보존한다. 여러 루트를 한 번에 등록하면 전체 루트를 증분 검증하며 기존 유효 캐시는 재사용한다.
- Worker는 설정/채보/폴더 목록의 소유 복사본으로 작업하고 결과 mailbox와 Windows 메시지로 알린다. UI 객체를 직접 수정하지 않는다. 진행 메시지는 약 100ms 간격으로 제한한다.
- 설정창·연습창·플레이·리절트 중 결과 적용을 보류한다. 닫거나 곡 선택으로 돌아오면 UI 스레드가 반영한다. 취소/종료 시 worker를 join하고 미게시 결과를 비운다. 예상 밖 스캔 오류에서는 기존 목록을 보존한다.
- 내부 링크/정션 디렉터리는 재귀 탐색하지 않는다. 등록 루트 자체의 링크는 Windows handle로 실제 경로를 확인해 중복을 줄인다. 조회 실패 시 등록 정보를 유지한다.
- 캐시만 보고 남아 있는 삭제/이동 채보는 플레이 준비 전에 실제 파일 존재를 확인해 차단한다.

## 6. 검증 결과

최종 Release 빌드 성공. 기본 실행 파일을 갱신했고 기능별 배포 실행 파일은 만들지 않았다.

최종 관련 CTest **13/14 통과**:

- 통과: BmsCoreTests, BmsLibraryTests, BmsSongGroupingTests, BmsSongSelectionTests, BmsSongLibraryUiTests
- 통과: BmsRmlSongListTests, BmsRmlSettingsHostTests, BmsSettingsPhase6Tests, BmsSettingsControllerTests
- 통과: SevenManiaSkinBindingTests, SevenManiaSkinApplicationTests, BmsFrameTests, BmsLowLatencyTests
- 실패: **BmsRmlSongListHostTests** — `buffered selection repaint left stale, blank or inconsistent rows`

실패를 캡처해 비교한 한 전환에서는 421×541 화면 중 좌측 모서리 11픽셀만 달랐고 채널 차이는 최대 7/255였다. 제한된 허용 오차를 실험했지만 다른 프레임에서는 계속 실패해 **실험은 되돌리고 원래 엄격한 검사를 유지했다**. 실제 원인을 확정하거나 렌더링 문제가 수정됐다고 주장하지 않는다. 스크롤 원위치 검사도 중간 실행에서 간헐적으로 실패했지만 최종 실행은 통과했다.

기존 그룹화 테스트의 “같은 디렉터리면 다른 제목도 합친다”는 검사는 이번 요구사항과 충돌하므로 별개 곡 분리를 확인하도록 변경했다. Host 차분 fixture에는 동일 음원 집합을 명시했다. 재그리기 검사를 통과시키기 위한 기준 완화는 최종 코드에 없다.

자동 검증 범위:

| 요청 사례 | 실제 확인 |
|---|---|
| 기본 Songs / 외부 한 개·여러 개 | 임시 실제 BMS 폴더 인덱싱 |
| 중복·대소문자·중첩·기본 루트의 상위 등록 | 인덱스 경로 집합과 개수 확인 |
| 등록 해제 후 원본 보존 | 실제 원본 파일 존재 확인 |
| 등록/보기 설정 재실행 유지 | 별도 INI로 sources 객체 재생성 및 UI 저장 재로드 |
| 캐시 시작·변경·추가·삭제·손상·저장 실패 | 임시 캐시/원본 파일로 회복과 갱신 확인 |
| 말단 생략·중간 분류·혼합·두 탐색 모드 | 모든 일반 탐색 경로를 순회해 각 채보가 정확히 한 번 나타나는지 비교 |
| 그룹/개별 보기 | C++/Rust 모델 모두 전체 채보 집합 보존 |
| 차분 wrap forward/backward | 기존 BmsSongSelectionTests 통과 |
| 기록 없음/기록/최고값 독립 갱신/조회·재로드 | 기존 격리 기록 INI 회귀 테스트 통과 |
| 스캔 중 폴더 이동/설정창/취소·종료 | 실제 UI worker 반영 보류·위치 보존, worker 취소/join 확인 |
| 한글·일본어·특수문자 경로 | 실제 경로와 ANSI INI 저장/복원 |
| 폴더/BMS/미지원 파일 드롭 | 실제 windowProc에 Windows HDROP 전달; 중복·거부 확인 |
| 캐시의 삭제 채보 플레이 진입 | 파일 이동 fixture로 로딩 진입 차단 확인 |
| 기본·기존 스킨 | 기존 바인딩/외부 스킨 적용 테스트 통과; 신규 바인딩 형식 요구 없음 |

C++ 대체 모델의 Library/Selection 테스트도 통과했다. 선택적 Rust 검색기 변경은 offline `cargo check` 성공이며 **Rust 검색기로 실제 전체 라이브러리를 검색한 검증과는 구분**한다. 기본 Release는 Rust 선곡 모델 ON, 선택적 Rust 파서/검색 backend OFF다.

## 7. 실측 성능

Release 진단으로 실제 Songs의 **788개 채보**를 읽었다. 기존 사용자 캐시를 삭제하지 않고 Validation 아래 별도 빈 캐시를 사용했다. OS 파일 캐시는 비우지 않았다.

| 스마트/원본 인덱스 전환 평균, 100회 | 3.55 ms |
| 그룹 인덱스 재구성 | 8.93 ms |
| 개별 채보 인덱스 재구성 | 9.95 ms |
| 진단 프로세스 private memory | 66.55 MiB |
| 진단 프로세스 peak working set | 91.94 MiB |

구현 중 모든 음원/이미지에도 `GetFileAttributesW()`를 추가 호출하는 검색 경로가 있었고, 이때 증분 검증은 3,942.08 ms였다. 디렉터리와 채보 후보에만 추가 조회하도록 고쳐 105.92 ms로 재측정했다. 이는 **이번 구현 내부의 수정 전후**이며 이전 배포 버전과의 공정한 벤치마크는 아니다. OS 캐시와 랜덤 채보 해석에 따른 그룹 수 차이도 있어 최초 인덱싱 시간 차이를 전부 이 수정의 효과라고 단정하지 않는다.

위 시간은 스캔 함수/메모리 모델 기준이다. 실제 첫 곡 목록 표시까지의 전체 시간, UI 이벤트·렌더링을 포함한 폴더 진입 지연, 실제 곡 선택 프레임 타임은 측정하지 않았다. 메모리 수치도 여러 메타데이터 벡터와 모델을 포함한 **진단 프로세스 전체**이며 캐시 단독이나 게임 전체 사용량이 아니다.

설정창 32회 열기/닫기에서 메모리 허용치 초과가 한 번 발생했다(워밍업 이후 약 35.4 MiB 증가). 별도 프로세스 비교에서는 기존 문서 약 15.0 MiB, 새 문서 약 18.0 MiB 증가로 두 검사 모두 통과했고 GDI/USER/GPU 사용량 차이는 0이었다. 최종 Phase6도 통과했다. 그러나 이 결과만으로 장기 메모리 증가가 없거나 누수 원인이 해결됐다고 말할 수 없다.

측정 명령: `BmsLibraryTests.exe --library2-profile <실제 Songs> <검증 출력 폴더>`. 출력은 내부 인덱스 비용이며 첫 화면 FPS 측정 도구가 아니다.

## 8. 남은 문제와 미검증 사항

- 엄격한 곡 목록 Host 재그리기 검사 실패의 근본 원인과 실제 사용자 화면 영향은 미확정이다. 캡처 비교를 넘어 확인 없이 렌더러를 재작성하지 않았다.
- 실제 사용자가 Explorer에서 드래그하는 수동 E2E, 실제 곡 미리듣기·플레이·리절트 복귀와 다양한 사용자 스킨의 수동 조작은 이번 검증에서 완료하지 않았다. 실제 OS 드롭 메시지와 UI 연결은 자동 테스트했다.
- 장시간 플레이/대규모 원격 드라이브, 프로세스 재실행 전체 소요 시간, 선곡 화면 P95/P99 프레임 타임은 미측정이다.
- 정션 순환은 코드에서 차단했으나 실제 정션/네트워크 장애를 조성한 실행 검증은 하지 않았다.
- 빈 폴더 목록은 캐시 스냅샷에서 즉시 복원되지 않고 백그라운드에서 조사한다. 마지막 위치가 빈 폴더이면 프로그램 재시작 때 기본 홈으로 복귀할 수 있다. 채보가 있는 폴더와 실제 선택 채보 복원은 유지한다.
- 새 관리 UI는 RmlUi 기타 탭에 있다. 기존 네이티브 설정 fallback에 동일한 관리 패널을 중복 구현하지 않았다. F2/F5와 폴더 드롭은 기본 창 경로를 사용한다.
- 등록 개수에 고정 배열 제한은 없지만 INI API·경로 길이·메모리 제약은 존재한다. 제거한 외부 루트의 캐시는 재등록 재사용을 위해 남을 수 있다.
- 파일 크기/수정 시각을 그대로 위장한 내용 변경까지 검출하는 해시 기반 검증, 파일 시스템 실시간 감시는 추가하지 않았다. 기존 증분 검사와 명시적 새로고침을 사용한다.

빌드/테스트/비교 원본 로그와 캡처는 `build-rmlui-song-list/Validation/library2-*`, `Validation/SongLibrary2UI`, `Validation/HostPixelDiagnostic`에 두었으며 Git에는 포함하지 않는다. 기존 사용자 소스 변경·스킨·미리 staged된 파일도 이번 커밋에서 제외한다.
