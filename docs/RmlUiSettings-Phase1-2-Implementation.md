# 설정 창 RmlUi 1·2단계 구현

2026-10-26 · `codex/rmlui-settings-ui-test`

## 범위와 실행

기존 설정창은 유지하고, 1단계의 값 기반 설정 명령과 2단계의 공통 RmlUi 수명·설정 입력 호스트를 구성했다. 설정창을 연 상태에서 **F9**를 누르면 별도 RmlUi 입력 실험 창을 사용할 수 있다. Escape/창 닫기로 닫는다. 키 배치 캡처 중 F9는 기존 키 입력으로 처리하며 실험 창을 열지 않는다.

이 실험 창의 체크박스·슬라이더·FPS 선택·문자 입력은 입력 검증용 독립 값이다. 실제 게임 설정에 반영되지 않는다고 창에 표시했다. 다섯 카테고리의 외형 교체와 실제 RML 설정 페이지 연결은 계획서 3단계 이후에 수행한다. 기존 설정창을 숨긴 컨트롤 저장소로 사용하는 방식은 추가하지 않았다.

기본 제공 파일은 `build-rmlui-song-list/Release/BmsPlayer.exe`다. 이번에도 기능별 이름의 별도 배포 실행 파일을 추가하지 않는다.

## 1단계: 값 기반 적용 경계

- `SettingsController.h`: HWND 없이 값 검증, 요약 ID의 원본 ID 매핑, 실제 값 Snapshot, 적용 실패 결과, 성공 시 저장, 지연 명령 큐를 제공한다.
- `SettingsActions.inl`: Main.cpp의 기존 전역 실행 상태와 장치 코드를 연결하는 백엔드다. `readSettingValue`/`applySettingValue`는 UI 컨트롤에서 값을 읽지 않는다. 같은 파일의 후반부에 있는 `settingControl`/`refreshSettingControls`만 네이티브 UI 어댑터다.
- 기존 WM_COMMAND/WM_HSCROLL은 컨트롤 값을 명령 값으로 변환한 뒤 컨트롤러를 호출한다. 퍼센트·FPS·배속·색상·구분선·체크 항목의 검증과 부수 효과를 한 경로로 모았다.
- FPS는 FPS 숫자, 배속은 0.25x 단위 정수, 밝기는 실제 퍼센트, 화면 모드는 저장값 0/1/2로 전달한다. 콤보 인덱스 역순 같은 UI 표현을 백엔드에 넘기지 않는다. 해상도는 현재 열거 목록의 선택 번호를 사용하며 백엔드에서 범위를 검증한다. 추후 RML 모델에서도 사용 가능한 해상도 목록을 먼저 구성해야 한다.
- `SettingResult`는 성공 여부·현재 실제 값·오류를 돌려준다. 메모리·CPU 적용이 실패하면 원래 값을 유지하고 실패한 요청값을 저장하지 않는다. 네이티브 컨트롤도 실제 값으로 되돌린다.
- 메인 창/렌더러 수명을 건드리는 GPU·DirectComposition·화면 모드·해상도 명령은 메인 창의 `WM_APPLY_SETTINGS`로 넘긴 뒤 처리한다. RmlUi 콜백 중 렌더러를 파괴하는 방식으로 연결하지 않는다.
- 일반 슬라이더는 기존처럼 이동 이벤트마다 적용·저장한다. 임의의 적용/취소 트랜잭션이나 저장 지연 정책은 추가하지 않았다. Esc는 여전히 변경을 보존하고 닫는다.
- `applyLaneKeys(array)`로 키 배열의 값 기반 검증·저장을 분리해 캡처 완료와 기본값 복원에서 같이 사용한다. 부분 키 입력 취소는 기존 상태를 유지한다.
- 파일 선택 대화상자는 기존 경로를 유지한다. 파일 복사 자체는 이미 값 기반 `copyUserBackgroundImage` 서비스로 처리되고 있어 새 RmlUi 호스트에 Windows 파일 대화상자를 복제하지 않았다.

현재 실행 상태를 별도 저장소에 통째로 복제한 것은 아니다. C++ 실행 값이 원본이고 Snapshot은 복사본이다. 3단계에서 데이터 바인딩을 연결할 때는 해당 Snapshot/모델을 문서 수명 동안 유효하게 보관해야 한다.

## 2단계: 공통 수명과 입력 호스트

### RmlUiRuntime

`RmlUiRuntime.h/.cpp`가 전역 Initialise/Shutdown, Windows 파일 접근, 시스템 글꼴, Win32 시스템 인터페이스, GDI+ 이미지 읽기, DX11 장치와 렌더 인터페이스를 소유한다.

목록과 설정은 공통 런타임의 공유 소유권을 받고 서로 다른 이름의 Context를 만든다. 각 Context의 문서·뷰 크기·렌더 타깃·비트맵은 해당 화면이 소유한다. 렌더 인터페이스는 공유하되 각 프레임 시작 전에 해당 화면의 viewport를 다시 설정한다. UI 스레드에서 순차 렌더링하며 백그라운드에서 RmlUi를 조작하지 않는다.

각 화면은 먼저 자기 Context를 제거하고 출력 자원을 정리한다. 마지막 소유자가 사라질 때만 RmlUi 전역 종료와 렌더러 파괴가 실행된다. 한 설정창의 파괴가 목록을 종료하지 않는다. 설정 호스트의 다른 스레드 접근은 런타임의 소유 스레드 검사로 거부한다.

기존 배너 이미지 디코더/썸네일 정책은 유지했다. 이는 현재 배너 사용에 맞춘 구현이다. 이후 설정용 일반 이미지·아이콘을 넣을 때 원본 크기·용도별 업로드 정책을 별도로 정해야 하며, 지금의 배너 처리 경로가 모든 이미지 디자인에 적합하다고 가정하지 않는다.

### RmlSettingsHost

`RmlSettingsHost.h/.cpp`는 별도 설정 실험 HWND에 Context와 문서를 연결한다.

- 마우스 이동·클릭·드래그·휠, Tab/Shift+Tab, 방향키, Enter, Escape 및 Alt+F4를 처리한다.
- RmlUi 공식 Win32 키 변환·IME 도우미를 사용하고 UTF-16 surrogate 상태는 호스트별로 관리한다. 한글과 보충 평면 문자도 확정 입력할 수 있다.
- 포커스 상실·캡처 취소 때 눌린 키/마우스 상태와 IME 조합을 정리한다. 정상 마우스 버튼 해제에 따라 발생한 캡처 변경을 드래그 취소로 잘못 처리하지 않는다.
- 메인 메시지 루프는 호스트 소유 입력을 먼저 전달한다. 해당 입력에 기존 `IsDialogMessageW`나 게임 키 처리기를 중복 적용하지 않는다.
- 리사이즈·DPI 변경 때 뷰와 비트맵을 갱신한다. 프로세스 전체의 기존 DPI awareness 정책 자체는 변경하지 않았다.
- 메모리 렌더 타깃에 완성한 프레임을 한 번에 BitBlt한다. 입력/갱신 요청이 없으면 기존 결과를 복사한다. 숨긴 창은 타이머로 다시 그리지 않는다.
- 문서는 열 때 한 번 로드한다. 드래그마다 문서를 재생성하지 않는다. 실패한 실험 창은 기존 설정창과 목록을 사용할 수 있는 상태로 정리한다.
- 기본 창/설정창이 종료될 때 실험 창도 정리한다. 렌더링 오류는 디버그 출력에 남기고 실험 창만 닫는다.

`Assets/UI/settings-probe.rml`은 2단계 입력 검증용 문서다. RmlUi는 브라우저 기본 스타일을 제공하지 않으므로 block 배치, 슬라이더 내부 track/bar, 선택 목록과 스크롤바, 버튼의 키보드 포커스 스타일을 명시했다.

## 빌드 옵션

| 옵션 | 역할 |
| --- | --- |
| `BMS_ENABLE_RMLUI` | 전체 런타임 사용. OFF이면 두 화면 옵션과 관계없이 스텁/기존 UI 사용 |
| `BMS_ENABLE_RMLUI_SONG_LIST` | 곡 목록 RmlUi 표시 |
| `BMS_ENABLE_RMLUI_SETTINGS` | F9 실험 호스트. 처음 구성할 때 목록 옵션 값을 기본으로 사용 |

기존 CMake 캐시에 저장된 옵션은 명시적으로 바꾸기 전까지 유지된다. 설정 호스트만 켠 조합과 전체 OFF 조합을 따로 검증했다. 마지막에는 세 옵션을 ON으로 복원해 기본 실행 파일을 빌드한다. Lua 런타임이나 새 인터프리터는 추가하지 않았다.

## HUD 이미지 교체

첨부한 `splash.png`를 변형 없이 `Assets/hud-icon-slot.png`로 복사했다. 원본은 64×64 PNG이며 알파 채널을 그대로 유지한다. 원본과 소스 파일의 SHA-256은 `4DA47C20646C61CE3F804B75A90379F3B8296BAF364E1613B49CB2B960B3DC74`로 같다. 이후 기본 빌드의 Assets 복사 단계에서 실행 폴더에도 같은 파일이 배포된다. 부팅용 `startup-splash.png`는 다른 파일이므로 교체하지 않았다.

## 검증과 한계

기본 Release 구성에서 관련 테스트 6개가 통과했다. 전체 RmlUi OFF 구성의 기준/컨트롤러 테스트 2개와 설정 호스트만 ON인 구성의 호스트 테스트도 통과했다. 입력/드래그 측정 한 회는 36프레임, 렌더링+readback 누적 19.7367ms(프레임당 약 0.55ms)였다. 이는 테스트 중 해당 구간만의 시간이며 전체 입력 지연이나 실제 게임 프레임 시간을 뜻하지 않는다.

- `BmsSettingsControllerTests`: 단위·범위 보정, 잘못된 값 거부, 요약 매핑, 적용 실패 시 원래 값/저장 횟수 유지, 이벤트 밖에서 큐 처리.
- `BmsSettingsPhase0Tests`: 기존 62개 INI 키 보존, 네이티브 탭/요약/저장·닫기 기준 유지. 추가로 HWND가 없는 상태의 직접 적용과 키 배열 검증.
- `BmsRmlSettingsHostTests`: 실제 Context·Win32 호스트를 통한 마우스 체크·드래그, 키보드 슬라이더·선택 목록, Tab/Shift+Tab·Enter·Escape, 한글·이모지, 크기/DPI 메시지, 포커스/캡처 취소, 외부 스레드 접근 거부.
- 같은 테스트에서 목록과 호스트 동시 사용, 목록을 먼저 닫기, 설정을 먼저 닫기, 반복 개폐, 문서 누락 후 복구, 설정 단독 초기화를 확인한다.
- 기존 목록 렌더링·호스트 테스트와 Display 테스트도 확인한다. 결과 자료는 빌드 폴더의 `Validation/RmlSettings/settings-input-probe.png`, 드래그 중 프레임 수·렌더링+readback 누적 시간이다.

입력 테스트는 숨김 HWND에 메시지를 전달하는 재현 테스트다. 물리 키보드/마우스, IME 후보창, 실제 다중 모니터 DPI 이동, 실제 GPU/오디오 장치 설정 성공을 모두 검증했다는 의미는 아니다. 드래그 측정은 테스트 화면의 합성 부하이며 전체 설정 UI나 실제 게임의 성능 보장이 아니다.

다음 단계는 이 호스트 안에 설정 외형을 만들고 단순 설정부터 실제 컨트롤러에 연결하는 3단계다. 기존 네이티브 설정창은 그 전까지 기본 경로로 유지한다.
