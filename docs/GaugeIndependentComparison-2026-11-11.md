# 독립 게이지 계산기 대조 기록

## 구현 경계

`IndependentGauge.h`와 `IndependentGaugeShift.h`는 별도 구현 담당자가
수치·입출력 명세를 받아 작성했다.
구현 담당자는 기존 GPL 개작 파일과 기준 구동기의 소스를 열지 않았다고 보고했다.
이는 작업 절차에 대한 기록이며, 동일 모델·공유 작업 공간에서의 작업만으로
법적 독립성이나 라이선스 적합성을 보증하지 않는다. 기존 GPL 파일과 출처는
별도 검토가 끝나기 전까지 유지한다.

## 실행 대조

기준: beatoraja `43073536893d7a95be42a85044ffa91143c053a9`의
`GaugeProperty.java` 및 `GrooveGauge.java`. 원본 Java 파일을 임시 빌드
디렉터리에서 컴파일해 실행했다. 필요한 주변 클래스는 최소 테스트 대역을
사용했으며, BMSModel에서 TOTAL과 노트 수만 공급했다. 원본 Java 파일은
프로젝트 소스나 배포물에 복사하지 않았다.

7KEYS와 beatoraja 내장 LR2 각각에 대해 9종 게이지, 6종 판정, TOTAL
경계, 1~1500개 노트, 시작값 및 판정 배율을 조합한 **532,224개 단일
이벤트**를 비교했다. 허용 오차 0.00005에서 차이 0건이었다.
`tests/fixtures/beatoraja-gauge-4307353.csv`는 이 실행의 4,536개 경계
사례이며 CTest에서 재검증한다.

LR2oraja 브랜치 `c1c8e4e0148abd318a9375de1631227cc383d0e4`의
`GaugeProperty.java`와 `GrooveGauge.java`도 같은 방식으로 실행했다. 9종
게이지의 TOTAL·노트 수·32% GUTS·2% 실패 경계를 포함한 456,192개
단일 판정 조건에서 같은 허용 오차로 차이 0건이었고, 그중 11,340개를
`tests/fixtures/lr2oraja-gauge-c1c8e4e.csv`에 보관해 회귀 검증한다.
LR2oraja의 저노트 수 피해 보정은 beatoraja 내장 LR2와 다르다.

이 검증은 계산기 비교다. 실제 채보 파싱, LN/CN/HCN 시간 누적, 스크래치,
자동 전환 순서, 플레이 기록, LR2oraja의 판정 타이밍 및 실제 게임 프레임 성능의 일치를
보장하지 않는다. 지뢰와 HCN 틱은 별도의 독립 단위 테스트로 검증했다.

독립 계산기와 전환기는 `--gauge-compat-test` 게임 경로에서 사용된다.
`--gauge-profile=7keys`, `--gauge-profile=lr2` 또는
`--gauge-profile=lr2oraja`로 시험할 수 있고, `lr2`는 beatoraja 내장
LR2 표를 의미한다. 해당 경로는 플레이 기록을
저장하지 않으며, 기본 실행은 기존 게이지를 계속 사용한다. 일반 플레이의
LR2oraja 시험에서는 고정한 원본 `BMSPlayerRule.java`의 기본 TOTAL을
사용한다. BMSON 1.0은 파싱 시 보존한 원래 상대 비율을 적용하며, 변환된
기존 TOTAL을 다시 비율로 해석하지 않는다. 연습 모드는 기존 TOTAL 처리를
유지하므로 LR2oraja의 연습 모드 TOTAL 호환성은 미검증이다. EMPTY_POOR
판정 발생, HCN 스케줄러 및 설정·기록 UI는 아직 완료되지 않았다.

2026-11-12에는 시험 경로의 미입력 스캔에서 CN/HCN 시작을 놓친 경우에만
꼬리의 POOR를 게이지에 추가로 전달했다. 일반 LN과 기존 비시험 경로는 한 번만
반영하며 기존 점수·판정 처리는 바꾸지 않는다. 실제 미입력 함수로 LN, CN,
HCN, 세 시험 프로필 및 기존 경로를 검사했다. HCN 몸통 틱의 시각과 자동 전환 평가 순서는
여전히 기준 구현과 일치한다고 확인되지 않았다.

## 기존 재생 호환성 테스트의 픽셀 불일치

2026-11-11 Release 재실행에서 `BmsCompatibilityPlaybackTests`는 지뢰·
롱노트 입력 구간을 지난 뒤 POP'N 9키 화면의 (360,459) 픽셀을 비교하다
실패했다. CPU 값은 `0x05070A`, GPU 값은 `0x05070B`로 파란색 성분이
1 차이 났다. 이 수치는 실패 지점을 좁힌 관측값이며, 반올림이나 특정
렌더러가 원인이라는 증거는 아니다. 실제 표시 결과와 실패 원인은 계속
조사해야 하므로 테스트의 비교 허용치를 임의로 늘리지 않았다.
