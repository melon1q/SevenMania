# 자원 표시와 건반 이미지 렌더링 최적화

현재 사용자 설정은 FPS 무제한, GPU 렌더링 꺼짐, 자원 사용량 표시 켜짐,
CPU/메모리/GPU 상한 100%, BGA 밝기 20%, 배속 6.00x였다.
500 FPS 증상을 프레임 제한으로 설명할 수는 없었다.

실제 energy trixxx의 normal.bms, 30~32초 구간을 2,000프레임 그려 비교했다.
게임과 같은 건반 이미지, 콤보/판정, 자원 표시를 포함하도록 기존 측정 도구를 보완했다.
기존 도구는 사용자 건반 이미지와 자원 표시 비용을 빠뜨리고 있었다.
비교 기준은 이번 수정 전 작업 상태이며, 개인 곡과 측정 CSV는 커밋하지 않는다.

| 구간 | 수정 전 평균 | 수정 후 평균 |
|---|---:|---:|
| 자원 사용량 텍스트/윤곽선 | 0.755ms | 0.025ms |
| 이미지 건반 포함 컨트롤러 | 0.212ms | 0.161ms |
| 화면 전송을 제외한 전체 렌더링 | 1.343ms | 0.657ms |
| GDI 화면 전송을 포함한 프레임 | 2.236ms | 1.362ms |

첫 세 행은 같은 설정으로 실행한 2,000프레임 검사의 평균이다.
마지막 행은 각 조건을 세 번 실행한 평균값의 중앙값이다.
이는 실제 채보를 사용하는 렌더링 부하 검사이며 오디오, 실제 키 입력, 영상 디코딩을
포함한 인게임 FPS 측정은 아니다. 특히 GDI 화면 전송 시간은 Windows 합성과 다른 앱
부하에 따라 편차가 있어, 모든 환경에서 1,000 FPS가 나온다고 보장하지 않는다.

## 변경

- 자원 표시 텍스트를 별도 캐시에 보관한다. 숫자나 폰트가 바뀔 때만 글자를 만들고,
  매 프레임 투명한 이미지를 합성한다. 기존의 얇은 흰색 글자와 검은 윤곽선을 유지한다.
- 건반 이미지의 확대, 알파 처리, 눌림 효과를 상태별로 캐시한다. 이미지 재로딩과
  레인 폭 변경 시 갱신하며, 턴테이블 회전과 키 입력은 매 프레임 반영한다.
- 자원 표시가 꺼져 있고 CPU 제한이 100%인 경우 메인 루프의 자원 조회를 생략한다.
- 진단 빌드 CSV에 자원 조회, 사용량 표시, 컨트롤러 비용을 별도 항목으로 기록한다.
  배포 빌드에는 진단 수집 코드가 들어가지 않는다.

## 검증과 재현

Display/GPU 테스트를 통과했다. 건반의 알파/눌림/같은 크기 이미지 교체와,
사용량 표시의 흰 글자/검은 윤곽/투명 배경/캐시 반복/숨기기를 검사했다.
GPU 모드에서도 모든 레인의 입력 효과와 애니메이션을 강제한 1,000프레임 검사를 완료했다.

```powershell
cmake --build build --config Release --target BmsRenderTests BmsDisplayTests BmsGpuTests
ctest --test-dir build -C Release -R '^(BmsDisplayTests|BmsGpuTests)$' --output-on-failure
build/Release/BmsRenderTests.exe '<chart.bms>' '<trace.csv>' 6 30 off steady '<settings.ini>' offscreen 2000 0.001
```

`offscreen`을 `gdi` 또는 `gpu`로 바꾸면 화면 출력도 측정한다.
마지막 두 인수는 프레임 수와 프레임당 채보 시간 증가량이다.
사용자 설정 파일은 읽기만 하며, 비교용 설정과 실행 파일은 빌드 폴더에만 저장한다.
